# macOS 0.1.0-m4.6 — подготовка общего прогона

Изменения: ранний кадр до чтения SQLite и поиска IPC, отдельное состояние ошибки запуска, короткий текст установки
службы, пять шагов в DMG, фон внутри пакета, чистый корень образа, отдельный артефакт installer-macOS в Actions.
Исправление VPN из решения 588 включено без изменений: оба направления собственного TUN разрешены без состояния pf.

## Автоматические проверки

- Полный локальный прогон Release: 2413 всего, 2290 успешно, 0 ошибок, 123 пропуска по ОС/правам/долгому прогону.
  На машине работала установленная служба; тесты без root ее не заменяли. Реальные системные TUN/pf/DNS здесь пропущены.
- Три новых UI-теста: кадр до завершения подготовки и отзывчивость, запуск в фоне без окна, ошибка вместо бесконечного
  индикатора. Три мутанта по очереди убирали Show, показывали фоновое окно и оставляли индикатор при ошибке: каждый
  дал ровно один ожидаемый отказ. После восстановления — 3/3, затем полный прогон выше.
- `dotnet format` и `git diff --check` — без замечаний.
- Пакет: подпись ad-hoc цела после упаковки, программа/ярлык/фон на месте, `.background` и `.fseventsd` в корне отсутствуют.
  Фон LZW 1.8 МБ с плотностями 1x/2x, серое поле 4096 × 4096 точек; инструкция занимает 720 × 600 точек.
- Замер отдельной тестовой копии с пустой папкой данных и `--demo`: от Main до запроса первого кадра 701 мс, до готовности
  1033 мс; готовность замечена через 3.34 с от запуска процесса. Это не проверка первого запуска скачанного файла через
  Gatekeeper: задержку macOS до Main и пользовательский сценарий этот замер не подтверждает.

## Проверка пользователем

По просьбе пользователя дальнейший запуск приложения, вид DMG в Finder, изменение размеров окна, обновление службы
через системный запрос и подключение на M4 оставлены ему. Старая проблема 40–50 с не воспроизведена; быстрый запуск после
проверок macOS нельзя гарантировать без испытания скачанного DMG на его машине. Системные предупреждения не сокращаются
приложением; Developer ID и нотаризация по-прежнему отложены.

Для VPN ранее прошел реальный тест HTTP/DNS под pf в CI 42389924479 на обоих стеках System и gVisor; до исправления
System падал после включения pf в CI 42389200046. Это проверка стенда, не подключения к серверу пользователя.
Порядок обновления и данные при ошибке — [first-run-service.md](first-run-service.md).
