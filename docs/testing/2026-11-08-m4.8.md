Код выпуска: `c7eaba94a0d9372a923b75fbeb09d0dc20040ffe`. DMG — Apple Silicon (osx-arm64).
SHA-256: `666e4d7ae8c0ff7af998c3516ab294b9d799607451d15a828117c804daf3b656`.

## Причина отказа сети

Отчет пользователя m4.7: служба и TUN запущены, IP сервера получен, но сайты по имени не открываются.
`ScutilDns` заменял DNS физической сети адресом туннеля. macOS привязывала этот адрес к en0,
и системные DNS-запросы не доходили до TUN. Прямой запрос UDP к тому же адресу и HTTP по IP проходили,
поэтому прежние тесты и зеленый статус не обнаруживали отказ резолвера ОС.

В [воспроизводящем прогоне](https://github.com/rvburov/private-gateway-client/actions/runs/42414978050)
`Real_tun_carries_http_and_dns_with_pf` завершился таймаутом системного DNS на System и gVisor.
В журнале `scutil --dns` у DNS туннеля указан `if_index ... (en0)`.

В [прогоне исправления](https://github.com/rvburov/private-gateway-client/actions/runs/42416173389)
оба сценария прошли: системный резолвер получил адрес контролируемого DNS через TUN, HTTP открыл сайт по имени
под настоящим pf. Новый собственный дополнительный резолвер не привязан к физической сети.
Старые копии DNS восстанавливаются при обновлении; остановка и перезапуск удаляют собственную DNS-запись.

> Исторический отчет версии m4.8. В m4.9 отдельный строгий режим возвращен по уточнению пользователя.
> Актуальная инструкция — [первая установка и обновление](first-run-service.md#обновление-до-010-m49-возврат-строгого-режима).

## Kill Switch

Включенный Kill Switch сохраняет блок после ручного отключения VPN, включая отключение из трея и удаление
активного сервера. Сеть открывается после выключения тумблера с подтверждением. Дополнительный «Строгий режим»
убран из десктопа; старые поля IPC сохранены. Отдельная подтверждаемая пауза для входа в Wi-Fi остается.
Мутант прежнего условия `Protection.StrictMode` провалил новый тест интерфейса; исправленный вариант прошел.
