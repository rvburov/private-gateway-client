# Первая установка: служба и разрешение VPN на каждой ОС

Главная проверка (просьба пользователя 2026-11-06): человек ставит программу впервые и доходит до работающей защиты. На
десктопе это экран «Установка службы» (шаг 1 из 2), на телефоне — системный запрос разрешения VPN при первом подключении.
Здесь — как это устроено на каждой ОС, что проверяет CI и что проверяется только на настоящем устройстве.

## Как ставится служба

| ОС и способ | Кто ставит службу | Что видит пользователь |
| --- | --- | --- |
| Windows, MSI | установщик MSI (действие `InstallService`, от SYSTEM) | запрос UAC при установке MSI; в первом запуске шаг службы уже «Готово» |
| Windows, архив или сборка из исходников | окно: «Установить» → `PrivateGateway.Service.exe --install --owner <SID>` через UAC | «Установка службы» → запрос UAC → этапы с процентами → «Готово» |
| macOS, DMG | окно: «Установить» → `osascript … with administrator privileges` | «Установка службы» → пароль администратора → этапы → «Готово» |
| Linux, .deb и .rpm | окно: «Установить» → `pkexec PrivateGateway.Service --install` (пакет при обновлении переставляет службу, которую ставило окно) | «Установка службы» → запрос пароля polkit → этапы → «Готово» |
| Linux, архив или сборка из исходников | окно, так же через pkexec | то же |
| Android | службы нет: VPN держит приложение (VpnService) | при первом подключении — системный запрос «Запрос на подключение» → «ОК» |
| iOS | службы нет: туннель — расширение Packet Tunnel | при первом подключении — «Private Gateway хочет добавить конфигурации VPN» → «Разрешить» и код телефона |

Сборка из исходников (`dotnet run --project desktop/src/Client.UI`) ставит автономную службу разработки из
`artifacts/dev-service/<конфигурация>` (с .NET и ядрами); ее готовит `dotnet build PrivateGateway.slnx`. Без этой сборки
окно ставит прежнюю службу или не находит ее вовсе ([guide.md](../user/guide.md)).

## Чего CI не проверяет — только на устройстве

- Сами окна ОС: запрос UAC, пароль администратора macOS, запрос polkit на Linux. CI работает с правами, и этих окон в нем
  нет. Отказ в них («Нет») окно отличает от ошибки — проверено на подставном установщике. Тест DMG передает
  установщику заблокированный `SIGCHLD`, как при системном запросе прав на macOS, и проверяет, что служба отвечает.
- Android: системный запрос «Запрос на подключение» на эмуляторе нажимается тестом; на настоящем телефоне вид окна зависит от
  оболочки производителя — его стоит увидеть своими глазами.
- iOS: запрос на добавление конфигурации VPN и код телефона — только на iPhone (симулятор туннеля не поднимает).

## Проверка на вашем устройстве

### Windows
1. Удалите прежнюю версию: «Параметры» → «Приложения» → «Private Gateway» → «Удалить».
2. Поставьте свежий MSI со страницы выпуска и запустите программу.
3. На экране «Установка службы» строка «Служба Private Gateway» — «Готово». Если нет — нажмите «Установить» и разрешите
   запрос UAC.
4. Не вышло — под кнопкой будет причина отказа словами: пришлите снимок.

Сборка из исходников: `git pull`, затем `dotnet build PrivateGateway.slnx`, затем `dotnet run --project
desktop/src/Client.UI`. Надпись «Служба не установлена — подробности в журнале» значит, что запущена сборка старше 28 октября:
с 8b822b8 окно пишет саму причину.

### macOS

Сетевые тесты и упаковку DMG запускают по очереди. Упаковка заново загружает ядра и заменяет файлы, которыми пользуются тесты.

1. Откройте DMG, перетащите Private Gateway в «Программы» и запустите (первый запуск — по инструкции в окне образа).
2. «Установка службы» → «Установить» → пароль администратора → этапы → «Готово».
3. После обновления приложения откройте «Настройки» → «О программе» → «Обновить службу». Версии окна и службы должны совпадать.
4. Отдельный запрос Связки ключей относится к сохраненным реквизитам. В нем приложение называется «Private Gateway».
   Введите пароль связки «Вход» (обычно пароль входа в Mac) и выберите «Разрешать всегда» для сохранения разрешения.
   «Разрешить» дает доступ один раз. У тестовой сборки с ad-hoc-подписью после замены приложения запрос может появиться
   снова: постоянный доступ между выпусками требует стабильной подписи приложения, отключать защиту Связки ключей не нужно.
5. При «Защищено» проверьте открытие сайтов и «Проверка» → «Проверить». Запущенные Xray и TUN сами по себе не доказывают
   доступ браузера. Если IP не измерен или сайты не открываются, сохраните «Экспорт отчета» до отключения VPN.

### Linux
1. Поставьте .deb (`sudo apt install ./PrivateGateway-…deb`) или .rpm и запустите программу из меню.
2. «Установка службы» → «Установить» → пароль в окне polkit → «Готово».

### Android
1. Поставьте APK, добавьте сервер, нажмите щит.
2. Система спросит «Запрос на подключение» → «ОК». Потом приложение спросит про уведомления.

### iPhone
1. Добавьте сервер, нажмите щит.
2. «Private Gateway хочет добавить конфигурации VPN» → «Разрешить» → код телефона.

### Обновление до 0.1.0-m4.7 и общий прогон на M4

Удалять приложение, службу и настройки перед обновлением не нужно. Сначала завершить интерфейс через меню строки
меню, заменить `Private Gateway.app` в «Программах» из нового DMG, открыть ее и нажать «Обновить службу», когда окно
предложит. В «О программе» проверить: клиент и служба — `0.1.0-m4.7`. Установка/обновление службы требует системного
разрешения; текст этого предупреждения задает macOS. Пароль в чат не присылать.

При блокировке первого запуска: в сообщении «Файл не был открыт» нажать «Готово», открыть «Системные настройки» →
«Конфиденциальность и безопасность», внизу «Все равно открыть», в следующем предупреждении снова «Все равно открыть»
и подтвердить запуск. Нажатие «Готово» во втором предупреждении закрывает его без запуска.

После обновления выключить Karing, проверить VPN отдельно на TCP Vision и XHTTP. Успех — страницы открываются,
проверка видит IP выхода, после отключения VPN обычная сеть возвращается. Если не работает: экспорт отчета сразу
после попытки, снимок главной и экрана «Проверка», обе версии из «О программе», выбранный транспорт и время попытки.
Ссылки серверов, UUID, пароли и ключи не нужны. Отдельно проверить левый/правый клик строки меню и открытие из Dock.

В m4.6 исчезновение значка могло сопровождаться падением и мешать завершению. Если старое окно не закрывается,
однократно завершить именно Private Gateway через «Мониторинг системы», затем заменить приложение. Профили и
службу удалять не нужно. В m4.7 проверить импорт и переход VPN/прокси, левый/правый клик, Cmd+Q и «Завершить» в Dock.
При новом падении нужны свежий отчет программы (если доступен), время и действие перед падением, системный отчет
`PrivateGateway-*.ips` из `~/Library/Logs/DiagnosticReports`. Пароли и ссылки подключения не присылать.

### Обновление до 0.1.0-m4.8: DNS и ручное отключение VPN

Удалять службу не нужно. Перед заменой окна выключить Kill Switch, отключить VPN и завершить интерфейс
через Cmd+Q. Заменить приложение в «Программах», открыть его и в «О программе» нажать «Обновить службу».
После системного запроса прав проверить обе версии: `0.1.0-m4.8`.

С выключенным Karing подключить выбранный сервер, затем проверить открытие обычных сайтов по имени.
Повторить для TCP Vision и XHTTP отдельно. При отказе экспортировать отчет, пока ошибка присутствует;
прислать отчет и снимки «Главной», завершенной «Проверки» и версий компонентов. Ключи и ссылки не нужны.

Отдельно проверить Kill Switch: включить его, подключить VPN, затем отключить VPN кнопкой-щитом.
Должны остаться «Интернет заблокирован» и блок трафика. Выключение «Блокировать интернет без VPN»
с подтверждением должно вернуть обычную сеть. Проверку на Mac пользователя выполняет пользователь.

### Обновление до 0.1.0-m4.9: возврат строгого режима

Исправление DNS m4.8 сохранено. Удалять службу не нужно: выключить Kill Switch с подтверждением,
отключить VPN, завершить приложение через Cmd+Q, заменить его в «Программах». Открыть «О программе»,
нажать «Обновить службу» и проверить, что клиент и служба показывают `0.1.0-m4.9`.

В «Настройках» → «Защита и утечки» снова есть отдельный «Строгий режим». С включенным Kill Switch:

1. Строгий режим выключен: подключить VPN и отключить его вручную — обычная сеть должна открыться.
2. Включить строгий режим и подтвердить: подключить VPN и отключить вручную — сеть остается закрытой.
3. Выключить строгий режим — обычная сеть снова открывается, Kill Switch остается включенным.

Настоящее подключение проверить с выключенным Karing, отдельно TCP Vision и XHTTP, открыть сайты по имени.
При отказе экспортировать отчет во время ошибки и прислать снимки «Главной», завершенной «Проверки»
и версий компонентов. Ключи и ссылки не нужны. Проверку установленной программы выполняет пользователь.

### Фоновая работа macOS и проверка после перезагрузки

Служба может быть установлена, но запрещена в «Системные настройки → Основные → Объекты входа и расширения».
Разрешите PrivateGatewayService. Запуск окна и автоматическое подключение VPN настраиваются отдельно.
При подтвержденном запрете новый экран предлагает открыть этот раздел и проверить снова, без переустановки.
Проверка не подключает VPN. После разрешения требуется ответ установленной службы; при неизвестной причине
окно сообщает, что состояние не определено. Если служба отвечает, прежний экран ошибки закрывается.

На десктопе Kill Switch находится только в «Защита и утечки». При его выключении с подтверждением строгий режим
также выключается и сохраняется выключенным. Повторное включение Kill Switch не возвращает строгий режим.
Выключение одного строгого режима сохраняет обычный Kill Switch. Режимы ручного отключения описаны в разделе m4.9 выше.
