# Долгий прогон перед выпуском

[`soak.yml`](../../.github/workflows/soak.yml) запускается ночью на `master`, вручную и из
`release.yml` на коммите тега. Каждый режим работает 30–60 минут: прокси на Linux, Windows и macOS;
VPN на Linux и Windows. Выпуск использует 30 минут на режим и не публикуется при ошибке.
Сокращение времени, пропуск ОС или режима не считается успешной проверкой выпуска.

На macOS Go должен быть установлен **до** `dotnet build`: сборка окна готовит службу разработки
и вызывает `scripts/get-singbox.sh`, который собирает закрепленный sing-box из исходников с CGO
и целевой macOS 13. Установка Go только перед отдельным шагом загрузки ядер происходит слишком поздно.
Версия действия `setup-go` закреплена так же, как в обычной CI.

В workflow добавлена установка Go перед сборкой. Это устраняет выявленную причину подготовки среды,
но успешность нового долгого прогона подтверждается только отдельным зеленым запуском на новом коммите.
Повторный запуск старого коммита не содержит исправления. Перед выпуском проверяются все задания
на коммите выпуска, включая полный долгий прогон в `release.yml`.

границей macOS 13; это не приемка физического компьютера с macOS 13.

Новый шаг установки Go в macOS-прогоне прошел. Задание `132971290423` начало шаг длительного теста
2026-11-15 в 21:56:55 UTC и не завершилось после предусмотренных 30 минут и ожидаемого таймаута 50 минут.
Прямая проверка API подтвердила активное задание. В трех прежних успешных запусках тот же этап занимал
30:06–30:09. Публикация блокируется до успешного полного прогона; наличие установщиков не заменяет этот результат.

Linux завершил оба режима за 30:05 и 30:05: 215 и 241 цикл, 6981 запрос проверки обхода, утечек нет.
Windows завершила оба режима за 30:00 и 30:12: 196 и 90 циклов, 5079 запросов, утечек нет.
Оба задания прошли без ошибок и пропусков. После этого заблокированный запуск отменен: macOS не завершилась
более чем за час. В журнале сохранилась только начальная строка режима и отмена; при уборке runner остановил
оставшиеся Xray, тестовое приложение и dotnet. Это не устанавливает конкретную фазу ожидания.

Причина пока не установлена. Возможные ожидания при остановке ядра, RPC, завершении тестовой службы и финализации
не считаются доказанным дефектом по одному времени выполнения. Журнал отдельного работающего задания через API
недоступен до его завершения; прежний скрипт дополнительно держит вывод дочернего теста в переменной до конца.

Отдельный диагностический запуск добавляет только тестовые отметки этапов и управляемые стеки потоков, без дампов
памяти и секретов. Короткая проба завершения не считается выпускным прогоном; после нее предусмотрен полный
30-минутный сценарий. Внешний наблюдатель ограничивает зависший диагностический процесс и сохраняет его последние
этапы. Обычные гейты выпуска не сокращаются и не заменяются этой диагностикой.

Первая нативная короткая проба на Mac завершила семь циклов за 1:05; все отметки GC и завершения служб получили
парные начало и конец. Следующий этап не запустился из-за ANSI-кодов SDK в текстовом разборе счетчиков.
Проверка переведена на машинный CTRF: ровно один успешный тест, без ошибок и пропусков; пустой, старый,
поврежденный или противоречивый отчет отвергается. Короткая проба не подтверждает полный 30-минутный результат.

Отказ пути от пользовательского устройства до VPS остается отдельным расследованием. Длительный тест использует
собственный локальный сервер и сам по себе не объясняет недоступность сервера владельца из нескольких клиентов.
