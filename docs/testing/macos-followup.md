# Повторная проверка MacBook M4: Связка ключей, выход, экран и флаги

Задачи пользователя от 2026-11-14. Приоритет — повторные 15–30 запросов пароля после обновления программы,
4–6 запросов при запуске; затем выход из аккаунта и переход с внешнего монитора на экран MacBook.
Проверочная сборка получается из Actions, без тега, GitHub Release и доставки выпуска на сайт.

## Установка и данные

1. До замены приложения сохранить защищенную резервную копию: «Настройки» → «Резервная копия» → «Ключи доступа»,
   задать пароль файла. Хранить файл и пароль у себя раздельно; присылать их не нужно.
2. Скачать ARM64 DMG проверочной сборки, перенести приложение в «Программы» с заменой прежнего. Не удалять данные
   программы или Связку ключей. Не возвращать старый бинарник без резервной копии: он не читает новое хранилище.
3. В «Настройки» → «О программе» сверить тестовую версию и коммит. Обычный номер 0.3.0 неоднозначен: прежние локальные
   сборки исправлений использовали тот же номер, что и официальный выпуск.
4. Обновить службу, если предложено. Запрос администратора для службы отличается от доступа к Связке ключей «Вход»:
   это разные разрешения ОС, их нельзя объединить в один парольный диалог программы.

## Пароль и 30 серверов

Проверять отдельно запуск, верхнюю круглую кнопку на странице серверов (замер доступности всех серверов),
обновление подписок и замену приложения следующей сборкой.

1. Открыть приложение с прежним списком из 25–30 серверов. Зафиксировать, какие окна появляются.
2. Разрешить доступ к общему ключу. Повторить замер всех серверов и обновление подписок несколько раз:
   уже перенесенные серверы не должны вызывать отдельные запросы Связки ключей.
3. Завершить приложение полностью, запустить снова, повторить замеры. Программа открывает один общий ключ на процесс,
   а не отдельный ключ для каждого сервера. Сама macOS может не спрашивать пароль при сохраненном доверии.
4. Повторить после замены бинарника другой проверочной сборкой. Уборка старых записей никогда не должна порождать
   системные окна. Отказ уборки не мешает использовать зашифрованную копию; удаленный вход или сервер не воскресает.
5. Проверить «Отказать» при запросе общего ключа: окно не закрывается, данные сохраняются; явное повторение действия
   позволяет снова запросить доступ. Пароль не записывается приложением и не попадает в отчет.
6. Экспортировать отчет. Раздел «Хранилище секретов macOS» содержит количества шифров, отложенных удалений и отметок
   удаления, а также открыт ли общий ключ в текущем процессе. Сам экспорт секреты не читает и пароль не запрашивает.

**Граница проверки:** права старых отдельных элементов Keychain программа не обходит. При первом чтении еще не
перенесенных элементов macOS может потребовать разрешение на каждый. Один пароль разблокировки связки не заменяет
эти разрешения. Отложенная очистка означает остаток старой копии, а не неперенесенный сервер; отчет не перечисляет
все элементы Keychain и не доказывает завершение миграции. Повторение серии при каждом обновлении уже перенесенных
серверов — дефект, а не нормальная цена обновления. Подробнее — [macos-keychain.md](macos-keychain.md).

## Выход из аккаунта

1. Включить VPN, блок при обрыве и строгий режим, затем выйти из аккаунта.
2. Убедиться, что обычный интернет работает, туннель остановлен, собственные блокировки сняты, прежние DNS и прокси
   восстановлены. Служба не должна снова подключаться или ставить прежний блок после перезапуска компьютера.
3. Войти снова: VPN, блок при обрыве, строгий режим, защита при загрузке, автоподключение и применение системного прокси
   выключены. Серверы, DNS-провайдер для будущего ручного VPN и остальные личные настройки сохранены.
4. Повторить в режиме внешнего прокси и при отключенном VPN. Чужой прокси или VPN не должен перенастраиваться.
5. Ошибки службы, DNS, firewall и записи настроек проверяются на тестовых подделках, без порчи рабочего компьютера.
   На экране входа при ошибке остается «Восстановить сеть», доступная без аккаунта. Успешный RPC не подменяется
   положением переключателя; ошибка очистки не отображается как завершенное восстановление.

Обычный обрыв связи при активном аккаунте сохраняет включенный пользователем блок при обрыве. Сброс настроек связан
с выходом и новым явным входом, а не с каждым открытием окна. На Android приложение останавливает свой VPN; системные
«Постоянная VPN» и «Блокировать подключения без VPN» отключаются пользователем в настройках Android. После нового входа
даже системный запрос постоянной VPN не начинает подключение: сначала пользователь должен нажать кнопку подключения.
После этого обычное автоматическое восстановление снова действует до следующего выхода или нового входа. На iOS аккаунта
сайта в текущем клиенте нет: проверяется безопасное начальное значение Kill Switch и сохранение ручного выбора.

## Мониторы и флаги

1. Открыть программу на внешнем мониторе, закрыть крышку MacBook; затем отключить монитор и открыть крышку.
2. Проверить нормальный размер текста, карточек и нижнего меню, отсутствие обрезки и совпадение кликов с кнопками.
3. Снова подключить монитор; перенести окно между экранами, изменить масштаб macOS, повторить после сна.
4. При неизменной сети пересчет масштаба сохраняет VPN-подключение и не требует перезапуска приложения. Если монитор
   подключал Ethernet через док, отключение самой сети проверяется отдельно от масштаба окна.
5. Флаги должны совпадать с прежним квадратным вариантом; отступы между эмодзи и названием сервера сохраняются.

Те же смены экранов проверить на Windows и Linux с разным DPI. Автотесты проверяют очередность обновлений и прекращение
обработки у закрытого окна; macOS smoke проверяет восстановление размера Metal drawable. Это дополняет, но не заменяет
реальное отключение монитора на M4.
