# Private Gateway Client — как начать

Один путь от загрузки до защищенного подключения. Подписи кнопок — как в программе (русский язык; в английском — те же
места). Что программа делает в сети сама — [PRIVACY.md](../../PRIVACY.md); коды ошибок `PGC-…` —
[docs/architecture/errors.md](../architecture/errors.md); сообщить о проблеме — форма «Сообщение о проблеме» в Issues
репозитория.

Что означают TUN, «Весь трафик», «Напрямую», правила и системный прокси, как они сочетаются и чем отличается сеть
Windows, macOS, Linux, Android и iOS — [«Как работает сеть в Private Gateway»](network.md).

## 1. Установка

Скачайте файл своей системы со страницы выпусков GitHub и рядом — `SHA256SUMS` (выпусков пока нет — ниже, «Пока
выпуска нет: сборка из исходников»). Сверьте загрузку:
`sha256sum -c SHA256SUMS --ignore-missing` (Linux, Git Bash на Windows) или `shasum -a 256 -c SHA256SUMS --ignore-missing`
(macOS) — строка вашего файла должна закончиться словом `OK`.

- **Windows** — `PrivateGateway-<версия>-win-x64.msi`: откройте и пройдите установщик. Программа пока не подписана
  сертификатом: если Windows покажет «Система Windows защитила ваш компьютер» — «Подробнее» → «Выполнить в любом случае».
- **Linux** — `.deb` (Debian, Ubuntu): `sudo apt install ./private-gateway_<версия>_amd64.deb`; `.rpm` (Fedora,
  openSUSE): `sudo dnf install ./private-gateway-<версия>.x86_64.rpm`.
- **macOS** (Apple Silicon) — `PrivateGateway-<версия>-osx-arm64.dmg`. Программа пока не подписана сертификатом Apple, и
  при первом запуске macOS ее не откроет. Те же шаги нарисованы в окне образа (по-русски и строкой по-английски):
  1. Откройте образ и перетащите **Private Gateway** в **«Программы»**.
  2. Откройте программу из «Программ» — в окне о проверке нажмите **«Готово»**.
  3. Откройте **«Системные настройки» → «Конфиденциальность и безопасность»**.
  4. Внизу, в разделе **«Безопасность»**, нажмите **«Все равно открыть»** и подтвердите. Это нужно один раз.

### Пока выпуска нет: сборка из исходников

Выпуски на GitHub появятся с первым тегом `v…`. До него проще всего — установщик последней сборки: CI собирает его при
каждом изменении. Войдите в GitHub → страница репозитория → «Actions» → слева «Сборка выпуска» → верхний запуск с
зеленой галочкой на ветке `master` → внизу «Artifacts» → `release-Windows` (`release-Linux`, `release-macOS`). Скачается
zip, в нем — те же файлы, что в разделе «Установка» выше (`PrivateGateway-0.1.0-win-x64.msi` и т. д.); ставятся так же.
.NET в них уже внутри, служба ставится установщиком. Хранятся 90 дней.

Сборка из исходников — для проверки свежих изменений (как собрать установщик самому — [docs/development.md](../development.md)). Один раз поставьте Git и .NET 10 SDK **для всей машины**
(служба работает от имени системы и .NET, поставленный только для вашей учетной записи — скриптом dotnet-install
или расширением VS Code, — не видит: установка службы так и скажет):

- **Windows** — в PowerShell: `winget install Git.Git Microsoft.DotNet.SDK.10`; дальше все команды — в Git Bash (он
  ставится вместе с Git).
- **Linux** — Debian, Ubuntu: `sudo apt-get install -y git curl unzip dotnet-sdk-10.0`; Fedora:
  `sudo dnf install -y git curl unzip dotnet-sdk-10.0`.
- **macOS** — `xcode-select --install` (Git), затем `brew install --cask dotnet-sdk` (нужен Homebrew).

Затем в терминале (на Windows — в Git Bash):

```bash
git clone https://github.com/rvburov/private-gateway-client.git
cd private-gateway-client
scripts/get-xray.sh && scripts/get-singbox.sh
dotnet build PrivateGateway.slnx
dotnet run --project desktop/src/Client.UI
```

`get-xray.sh` и `get-singbox.sh` скачивают ядра Xray и sing-box и сверяют их суммы с закрепленными в репозитории.
Оборвалась загрузка (связь с GitHub) — скрипт сам повторит до 6 раз, докачивая с места обрыва; не вышло и так —
запустите его снова позже.
`dotnet build` собирает и окно, и службу (пару минут в первый раз): без собранной службы не будет ни «Установка
службы», ни режима прокси. Откроется окно — дальше раздел «Первый запуск».

**Папка репозитория уже есть** (клонировали раньше) — `git clone` не нужен, он откажет: «destination path … already
exists». Закройте программу, если она запущена (значок в трее → «Выход»): иначе сборка упадет на занятых файлах. Затем
в терминале (на Windows — в Git Bash; в Проводнике: правой кнопкой по папке → «Open Git Bash here»):

```bash
cd путь/к/private-gateway-client
git status
git checkout master && git pull
scripts/get-xray.sh && scripts/get-singbox.sh
dotnet build PrivateGateway.slnx
dotnet run --project desktop/src/Client.UI
```

`git status` должен показать «On branch master» и «nothing to commit, working tree clean». Если он перечисляет
измененные файлы или `git pull` отказывает («Your local changes … would be overwritten») — остановитесь и ничего не
удаляйте: это ваши правки, их сначала нужно сохранить. Если `git status` пишет «not a git repository» — папка скачана
архивом ZIP, а не через Git: клонируйте рядом командами выше. Так же обновляться до свежей версии и потом.

Что повторять потом: просто запустить снова — только `dotnet run --project desktop/src/Client.UI`; после `git pull` —
`dotnet build PrivateGateway.slnx` и `dotnet run …`; ядра (`get-xray.sh`, `get-singbox.sh`) — когда `git pull` меняет
`shared/cores/xray.version` или `shared/cores/sing-box.version` (повторить их не вредно). **Служба уже установлена** —
она работает из своей копии (Program Files, `/opt`, на macOS — `/Library/Application Support`), и сборка ее не трогает:
после обновления «Настройки» → «О программе» покажет «Служба собрана из других исходников …» — нажмите «Обновить
службу» и подтвердите права администратора. Служба, поставленная до 27.10.2026, коммита не называет — там будет «(без
коммита)», обновить так же. Если вместо кнопки — «Служба рядом с окном собрана из других исходников …», окно запущено
без сборки службы: закройте программу, выполните `dotnet build PrivateGateway.slnx` и `dotnet run …` снова. Сверка — по
коммиту, поэтому и обновление, менявшее только документацию, попросит обновить службу: это быстро и ничего не ломает.

Команды одни на всех ОС: на Windows — в Git Bash (в PowerShell и cmd скрипты `scripts/…` не запустятся), на macOS и
Linux — в Терминале. Ядра скрипты берут только со сверенной суммой: она есть для Windows x64, macOS (Apple M1 и новее
и Intel) и Linux (x64 и ARM).

## 2. Первый запуск

1. «Начать».
2. «Установка службы» → «Установить». Система один раз спросит права администратора: служба держит VPN и блок при обрыве,
   даже когда окно закрыто. Без нее — «Без службы — только режим прокси» (защищен не весь трафик, блока при обрыве нет).
3. «Добавьте первый сервер» → «Добавить сервер» (или «Сначала посмотреть на демо-серверах» — подключение там
   имитируется).

## 3. Добавить серверы

Кнопка «Добавить ссылку или подписку» вверху окна, затем один из способов:

- «Из буфера обмена» — скопированные ссылки `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://`, `tuic://`,
  `wg` или адрес подписки (Hysteria2 и TUIC подключаются только на компьютере);
- «QR-код с экрана» — снимок области с кодом или картинка;
- «Ввести ссылку» — ссылки по строкам или адрес подписки `https://…` → «Проверить»;
- «Открыть файл» — ссылки, base64, sing-box JSON или Clash YAML.

В «Предпросмотре» видно, сколько найдено, новых, дублей и ошибок (строка и причина). «Название профиля» — как подписка
будет называться в «Настройки» → «Профили и подписки». Затем «Добавить N серверов».

Подписки обновляются по расписанию из «Профили и подписки» и по умолчанию только через VPN («Обновлять только через VPN»):
адрес подписки не уходит к провайдеру открытым.

## 4. Подключиться

1. «Серверы» → выберите сервер (задержка рядом — замер через сам сервер).
2. «Главная» → «Включить защиту». «Защищено» — весь трафик машины идет через сервер: браузеры, терминал, Git, фоновые
   службы.
3. Обрыв связи — «Подключение», трафик стоит (блок при обрыве), пока сервер не ответит снова. Программа переподключается
   только к выбранному вами серверу.
   Пока VPN не подключен, Windows пишет у сети «Нет подключения к Интернету»: блок закрыл ее проверку сети, сама сеть в
   порядке. Почему не подключается — «Проверка» → журнал: «Сервер не отвечает по TCP…» (сервер выключен или путь до него
   режется) или «Сервер отвечает по TCP…, но связи через него нет» (профиль не принят — проверьте ссылку).
4. «Выключить защиту» — сеть снова напрямую.

Режим — «Настройки» → «Режим»: «VPN · вся система» (по умолчанию) или «Только прокси» (часть программ пойдет напрямую,
блока при обрыве нет).

Для прямого внешнего SOCKS5, HTTP или HTTPS выберите «Только прокси» и заполните форму под переключателем:
адрес, внешний порт и авторизацию. Собственный VPS не нужен. VPN-сервер, локальный порт приложения и параметры
внешнего прокси сохраняются отдельно. [Настройка, охват и ограничения](external-proxy.md).

### Фоновый режим и автоматический запуск

В «Настройки» → «Основные» эти переключатели решают разные задачи:

- **«Фоновый режим»**: при закрытии окна прокси-клиент продолжит работать. Значок остается в трее или строке
  меню; нажмите его, чтобы снова открыть окно.
- **«Запускать вместе с Windows»** (macOS или Linux): клиент автоматически запустится в фоне при входе в систему.
- **«Подключаться при запуске»**: клиент автоматически подключится к выбранному серверу. Сам по себе запуск окна
  или работа в фоне не включает это подключение.
- **«Блокировать интернет при обрыве VPN»**: если связь с VPN пропадет, интернет остановится до восстановления
  защиты. В режиме «Только прокси» общей блокировки интернета нет.

В меню значка «Закрыть интерфейс» оставляет установленную VPN-службу работать. «Закрыть программу» при службе
пользователя завершает и клиент, и его прокси; это отличается от закрытия окна в фоновом режиме.

### Панель на IP VPN-сервера: что изменили

**Что было.** Клиент отправлял мимо VPN все соединения к IP сервера из выбранного профиля. Это давало самому
VPN путь до сервера без повторного попадания в собственный туннель. При этом защита разрешала прямое соединение
только на порт самого VPN. Когда TCP-профиль и панель использовали один порт 8443,
панель открывалась: адрес и порт совпадали с разрешением. После выбора XHTTP на 8444 панель на 8443 того же IP
по-прежнему шла напрямую, но уже не попадала под разрешение и блокировалась. Выключение «Блока при обрыве» не
помогало: пока VPN подключен, правила защиты все равно ограничивают трафик вне туннеля.

Это касалось адреса сервера **активного профиля**: при выборе другого сервера менялся и адрес исключения.
В коде нет постоянного IP конкретного владельца; порт 8443 у сайтов на других IP сам по себе не был запрещен.

**Что изменили.** Вместо исключения всего IP клиент дает прямой путь только точной паре «IP сервера + порт VPN».
Разрешения брандмауэра не расширяли, все порты сервера напрямую не открывали.

**Как теперь работает.** При XHTTP на 8444 соединение самого VPN идет напрямую, а панель на 8443 того же IP — через
VPN. Другие адреса идут по обычным правилам выбранного режима: в режиме VPN для всей системы — через VPN, с учетом
раздельного режима и настроек локальной сети. Если IP и порт сайта полностью совпадают с IP и портом VPN,
эта пара остается прямым исключением.
Поэтому маршрут панели зависит от пары адреса и порта, а не от ее названия.

Изменение пока проходит проверку в ветке разработки. Успешный CI и работа новой сборки на Windows пользователя
еще не подтверждены; проверка доступности панели описана в [пункте 10 проверки Windows](../testing/windows-check.md#10-панель-и-другие-службы-на-ip-vpn-сервера-решение-512).

## 5. Wi-Fi отеля или кафе

Сеть просит войти на своей странице, а защита ее закрывает: «Настройки» → «Защита и утечки» → «Войти в Wi-Fi» →
«Открыть», затем подтвердите «Открыть на 5 минут». Пока идет пауза, сайты и сеть видят ваш реальный IP;
через 5 минут защита вернется сама, раньше — «Вернуть защиту».

## 6. Проверить защиту

«Проверка» — внешний IP (какой адрес видят сайты), утечки DNS, IPv6 и WebRTC, сеть машины до и после VPN, замеры до
сайта. Что-то не так — «Экспорт отчета»: отчет обезличен, приложите его к сообщению о проблеме.

На десктопе в блоке «Задержка» остаются три отдельных измерения: «До сервера», «Через сервер» и «Новое соединение».
Их подписи, значения и время обновления сохранены; расчет количества кругов до сервера убран с экрана, но остается
в экспортируемом отчете для разбора проблем.

DNS-настройка и сетевая проба — разные сведения. На десктопе выбор по умолчанию явно называется Cloudflare;
подпись примененной политики не обещает отсутствия всех утечек. Прямая проба измеряет только IPv4 UDP/53:
«Ответ не подтвержден» означает недостаточный результат, а не доказанный обход. DNS-адреса адаптеров/TUN в
отчете — настройки ОС, не список внешних рекурсивных резолверов, который показывает браузерный DNS-тест.
Если ранее прямой ответ был получен, последующая тишина его не опровергает: предупреждение о прежнем открытом
пути сохраняется, а новый неподтвержденный замер показывается отдельно.

## 7. Удаление

- Windows — «Параметры» → «Приложения» → «Установленные приложения» → Private Gateway Client → «…» → «Удалить».
- Linux — `sudo apt remove private-gateway` или `sudo dnf remove private-gateway`.
- macOS — сначала служба: в «Терминале»
  `sudo "/Applications/Private Gateway.app/Contents/MacOS/PrivateGateway.Service" --uninstall`, затем Private Gateway из
  «Программ» в Корзину.

Удаление снимает службу и ее сетевые правила (блок при обрыве, маршруты, DNS): сеть возвращается прямой.

## Android

1. Установите APK, откройте программу.
2. «Добавить ссылку или подписку» — ссылка, подписка или «QR-код» (камерой или «Выбрать картинку») → «Добавить N
   серверов».
3. Выберите сервер → кнопка-щит. Android один раз спросит разрешение на VPN — «OK».
4. Блок при обрыве на Android — системный: «Настройки» программы → «Открыть настройки VPN» → Private Gateway →
   «Постоянная VPN» и «Блокировать подключения без VPN». Включить их может только пользователь; что включено, программа
   показывает в своих «Настройках».
