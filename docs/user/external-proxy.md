# Прямое подключение к внешнему прокси

Настольный клиент, 2026-11-05. Настройка находится в «Настройки» → «Основные» → «Режим».

## Как выбрать режим

- **VPN · вся система** подключает выбранный в списке VPN-сервер. Его дальнейший выход в интернет задает сам
  сервер: напрямую или через настроенный на нем прокси. Логин и пароль этого серверного прокси клиенту не нужны.
- **Только прокси** использует отдельный внешний адрес из формы под переключателем режима:
  устройство → внешний прокси → интернет. Собственный VPS и VPN-профиль для такого подключения не требуются.

Выбранный VPN-сервер и параметры внешнего прокси сохраняются независимо. Выбор другого VPN-сервера в списке
при работающем прокси сохраняет его для VPN. Явное «Подключить VPN» в карточке включает режим VPN.
Переход с VPN в прокси сохраняет существующий вопрос о сокращении охвата защиты.

## Настройка внешнего подключения

1. Выберите «Только прокси». Под переключателем появится форма.
2. Выберите протокол из данных доступа: SOCKS5, HTTP или HTTPS. HTTPS здесь означает HTTP CONNECT через TLS,
   а не адрес сайта, который вы хотите открыть.
3. Введите IP или домен без `http://`, пути и `логин:пароль@`. IPv6 допускается. Отдельно введите порт внешнего
   прокси: число от 1 до 65535. В тестовых примерах используются адреса вроде `192.0.2.20`, не рабочие серверы.
4. Выберите способ авторизации. Для «Логин и пароль» заполните оба поля точно как в выданных данных.
   Значимые пробелы в учетных данных не обрезаются. «Без логина и пароля» подходит, если внешний сервер допускает
   такой доступ, например по заранее разрешенному IP; приложение не настраивает это разрешение на сервере.
5. Нажмите «Сохранить прокси». Неполная форма не меняет действующее подключение. Если прокси уже работает,
   сохраненные изменения применяются через штатное переподключение; выключенный клиент сам не подключается.
6. Включите подключение кнопкой-щитом и запустите «Проверку». Сохраненные поля сами по себе не подтверждают
   доступность сервера, правильный пароль или работу UDP.

Если после смены режима внешняя цель еще не настроена, приложение не подставляет вместо нее VPN-сервер.
Ранее работавшее подключение отключается согласно явному выбору режима. Если при запуске службы режим или
редакция формы изменились, запоздавший запрос не подключает прежнюю цель.

## Внешний адрес и локальный вход — разные настройки

Адрес из формы — удаленный сервер. Например, внешний сервер может слушать порт `3128`, а клиент предоставлять
программам локальный вход `127.0.0.1:10808`. Один порт не заменяет другой.

Локальный HTTP/SOCKS-порт, доступ из локальной сети и управление системным прокси остаются в «Подключение и ядро».
Системный прокси направляет поддерживающие его программы на локальный вход приложения. Не нужно вводить туда
внешний адрес или выдавать программам пароль внешнего сервера.

## Охват, TCP, UDP и DNS

| Свойство | HTTP / HTTPS | SOCKS5 |
| --- | --- | --- |
| TCP | HTTP CONNECT через внешний сервер | Через внешний сервер |
| UDP | Не поддерживается этим протоколом подключения | Нужны UDP ASSOCIATE у внешнего сервера и UDP в программе |
| Шифрование участка до прокси | HTTPS — TLS с проверкой сертификата; HTTP — без TLS | Сам SOCKS5 этот участок не шифрует |
| DNS всей ОС | Не перехватывается | Не перехватывается |

HTTPS-сайт может дополнительно шифровать содержимое своим TLS независимо от протокола прокси. HTTP/HTTPS и SOCKS5
здесь описывают участок от клиента до внешнего прокси. Успешный TCP-запрос не доказывает наличие UDP у SOCKS5.

Через прокси идут программы, которые используют локальный вход или поддерживают системный прокси. Остальные
программы могут идти напрямую. Общего блока всей сети при обрыве в этом режиме нет. Сохраненные прямые правила
сайтов и разрешения локальной сети также учитываются; они не превращаются в запрет прямого трафика автоматически.

Выбор DNS относится к ядру обслуживаемых соединений, а не ко всей Windows/macOS/Linux. Собственный DoH браузера
остается отдельным DNS-путем. Для HTTP/HTTPS подходит DoH: Cloudflare, Quad9 или свой адрес HTTPS.
Обычный публичный DNS по IP использует UDP/53 и для HTTP/HTTPS не поддерживается: приложение сообщает об этом,
не меняя выбор и не отправляя запрос напрямую. Явно выбранное существующее исключение частного DNS локальной сети
остается прямым исключением. Подробности — [сеть и DNS](network.md).

## Хранение и сбои

Логин и пароль сохраняются только в защищенном хранилище ОС: DPAPI, Связка ключей или Secret Service. Если оно
недоступно, авторизация не сохраняется открытым текстом. Пропавший пароль не переключает профиль на доступ без
авторизации. В журнале и диагностическом отчете учетных данных нет.

Резервная копия с настройками и ключами переносит учетные данные внутри зашифрованного файла. Копия без ключей
возвращает адрес и выбранный способ авторизации, но требует повторного ввода логина и пароля. Ссылки на секреты
другой машины не используются; автокопия также зашифрована.

Состояние «Подключено» требует пробы через внешний выход. Неверный пароль, отказ TLS или неответивший сервер не
считаются успехом только потому, что открыт локальный порт. После обрыва действует выбранная политика повторов;
локальный прокси не получает скрытый прямой выход вместо отказавшего внешнего сервера. Это не закрывает сеть
другим программам, которые изначально не использовали приложение или имеют явные прямые исключения.

Для новой функции окно и служба должны поддерживать `external-proxy-v1`. Старая служба дает понятный отказ;
отсутствие ответа службы ограничено по времени и не называется доказанной несовместимостью.

Порядок проверки на своем компьютере — [чеклист](../testing/external-proxy.md).
