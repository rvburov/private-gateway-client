# Модель угроз

Цель продукта — анонимность в интернете для одного пользователя на своих устройствах: сайты и
сети по пути не должны видеть реальный IP, DNS-запросы и содержимое трафика, а сбой не должен
незаметно пустить трафик напрямую.

## Что защищаем

| Ценность | Почему важно |
| --- | --- |
| Реальный IP и местоположение | главное, что скрывает VPN |
| DNS-запросы | по ним видно, какие сайты открываются, даже при туннеле |
| Ключи серверов, UUID, пароли, адреса подписок | по ним можно подключиться к серверу пользователя или отследить подписку |
| Список серверов и история подключений | раскрывает, какими серверами пользуется человек |
| Целостность машины | служба работает с правами администратора |

## От кого защищаемся

| Противник | Что может | Ответ |
| --- | --- | --- |
| Сайты и трекеры | видят IP и DNS | весь трафик и DNS через туннель, проверка внешнего IP |
| Провайдер и сеть Wi-Fi (кафе, отель) | видят трафик и DNS, подменяют DNS, перехватывают вход в сеть | шифрование транспорта, DNS только в туннеле, пауза для входа в Wi-Fi — только по кнопке и на время |
| Обрыв связи, сбой ядра или службы | трафик молча уходит напрямую; после отключения сеть не возвращается | блок при обрыве включается до запуска ядра и держится в состояниях Connecting, Reconnecting, Blocked, Error; ядра не переживают службу (systemd, задание Windows); правила маршрутизации убитого sing-box служба убирает сама |
| Утечки мимо туннеля | IPv6, DNS ОС, WebRTC, локальная сеть, контейнеры и виртуальные машины со своим NAT | IPv6 блокируется, если сервер его не поддерживает; DNS ОС закрыт; локальная сеть по умолчанию запрещена; пересылка на Linux — только в туннель (Windows — открытый пункт) |
| Другой процесс пользователя на той же машине | обратиться к службе по IPC | канал с ACL и проверкой uid собеседника; служба не принимает конфиги, пути и команды — только описание сервера |
| Чужая программа или другой пользователь, занявшие адрес службы раньше нее | выдать себя за службу и получить ключи серверов | окно проверяет, кто на том конце: владельца pipe, uid процесса у Unix-сокета; доверяет только SYSTEM, администраторам, root и самому пользователю (для службы пользователя) |
| Подложенный файл рядом с программой или выше по дереву папок | запуститься вместо службы пользователя или ядра | файл службы — только рядом с программой или в точной папке сборки, ядро — рядом со службой или в `artifacts/cores`; поиска вверх по папкам нет |
| Программа пользователя, подменившая файл установленной службы или ядра | получить права SYSTEM или root | установка копирует службу и ядра в папку, куда пишут только администраторы или root (Program Files, /opt), и регистрирует службу оттуда; из папки пользователя служба от SYSTEM не запускается |
| Другая программа на машине в режиме VPN | войти во вход Xray на 127.0.0.1 и ходить через сервер в обход TUN и его правил | вход Xray для TUN — с именем и паролем по 128 случайных бит на каждое подключение, порт случайный; оба ядра получают их через stdin, не через файл или аргументы |
| Соединение с сервером, которое ушло бы в сам туннель | петля: соединение с сервером идет через сам туннель, и VPN не поднимается | адрес сервера разрешается до запуска и выводится из маршрутов TUN; Xray соединяется с этим адресом (решение 176) |
| Другой VPN на машине, включенный до подключения или на ходу | увести трафик мимо нашего туннеля, пока окно показывает «Защищено» | служба ищет чужой туннель с маршрутом ко всему интернету при подключении, при каждой смене сети и с каждой пробой сервера; нашелся без разрешения — подключение останавливается с `PGC-NET-010`, блок при обрыве остается |
| Человек с доступом к журналу или отчету | вытащить ключи и адреса | `SecretMasker` во всех журналах и отчетах |
| Сеть по пути к серверу подписки, сам сервер подписки | прочитать подписку по `http://`; прислать огромный или бесконечный ответ | предупреждение в предпросмотре при `http://`; загрузка не дольше 20 с и не больше 5 МБ после распаковки; адрес подписки — только в хранилище ОС и не попадает в ошибки; обновление по умолчанию — только через включенный VPN |
| Тот, у кого оказался файл резервной копии | прочитать список серверов, ссылки на подписки и, если их сохранили, ключи | файл всегда зашифрован паролем (не короче 8 знаков): PBKDF2-SHA256 600 000 повторов и AES-256-GCM; ключи — отдельной галочкой с предупреждением; автокопия перед восстановлением — под случайным ключом из хранилища ОС |
| Подмена ядра или обновления | запуск чужого кода с правами администратора | ядра скачиваются скриптом со сверкой контрольных сумм, обновление — с проверкой подписи |

## Что вне модели

- Противник с правами администратора на машине пользователя.
- Анализ трафика на уровне государства (корреляция по времени и объему) — частично смягчают
  REALITY и маскировка, но гарантий нет.
- Деанонимизация через учетные записи и отпечаток браузера — это не задача VPN.
- Сам сервер VPN: он видит трафик после выхода из туннеля; выбор сервера — ответственность
  пользователя.

## Правила, которые из этого следуют

1. Блок при обрыве включен по умолчанию; выключение — явным действием пользователя с
   подтверждением.
2. «Трафик зашифрован» — только когда это правда (`TrafficEncryption`): VLESS без TLS/REALITY —
   нет.
3. Внешний IP на главном экране — измеренный службой, а не предполагаемый.
4. Пауза для входа в Wi-Fi — с таймером и возвратом защиты по истечении.
5. Интерфейс не управляет сетью (тесты `Architecture`, анализатор RS0030).
6. Секреты — только в хранилище ОС; в Git, тестах, журналах, URL и аргументах процессов их нет.
7. Режим «только прокси» честно показан как неполная защита (желтый), блок при обрыве в нем
   недоступен. Служба пользователя (режим прокси без установленной службы) живет, пока живет окно.
8. Системный прокси в режиме прокси возвращается, как был, при отключении и остановке службы, а
   после сбоя — при следующем запуске (снимок в файле). Ошибка ядра его не снимает: программы с
   прокси остаются без связи, а не уходят напрямую.
9. Режим VPN — только где есть блок при обрыве; блок ставится до запуска ядер, держится при сбое
   ядра и после остановки службы, а проверки не обещают блок, которого нет.
10. Окно не показывает защиту, которой нет: без службы подключения не имитирует (имитация — только
   в демо-режиме `--demo`); без службы и после ее отказа — «защиты нет, трафик идет напрямую».
11. Мимо VPN — только осознанным выбором: раздельный режим выключен по умолчанию и показан с
   предупреждением; в режиме «Весь трафик» программы мимо VPN и правила «Напрямую» службе не
   уходят. Путь программы служба использует только для сравнения с процессом — не запускает и не
   открывает. Блок при обрыве открывает обходу один путь — выход `direct` sing-box (метка пакетов
   на Linux, программа sing-box в WFP), а не программы пользователя: другой процесс мимо туннеля не
   пройдет, даже если он называется так же.

Проверки, которые подтверждают правила на реальной машине, — этап «Защита» ROADMAP и экран
«Проверка» (утечки DNS, IPv6, внешний IP, блок при обрыве).
