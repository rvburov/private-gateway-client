# macOS: отсутствие результатов проверки и повторное подключение — 2026-11-15

Статус: исправления кода подготовлены для проверочной сборки `0.3.1-test.2`; результаты автоматических проверок — в
[Actions](https://github.com/rvburov/private-gateway-client/actions/workflows/ci.yml),
приемка этой сборки на M4 еще не подтверждена. Первопричина конкретного сетевого обрыва по отчетам не установлена.
Четыре предыдущих исправления владелец подтвердил отдельно: [приемка на MacBook M4](../../testing/macos-followup.md).

## Наблюдения владельца и отчеты

Третий отчет исключает несовпадение версий как достаточное объяснение ошибки диагностики. Отчеты собираются

Второй отчет содержит `app/dns ... context deadline exceeded`; это подтверждает отсутствие ответа DNS-over-HTTPS,
но не определяет, виноваты ли резолвер, путь через VPN или сервер. Ранний успешный TCP-запрос к серверу также
не доказывает исправность всего туннеля. Ключи, адреса серверов и пользовательские IP здесь не приводятся.

очистки Keychain не подтверждает связь этой ошибки с хранилищем; несовпадения версий окна и службы снова нет.

## Подтвержденные свойства прежнего кода

- `GatewayRpc.RunChecks` ожидает пробы выходного IP, IPv6 и DNS до формирования всех строк. Необработанная ошибка
  одной пробы прерывает общий ответ, включая локально известные состояния службы и блока при обрыве.
- `ServiceGatewayClient.RunChecksAsync` превращает неклассифицированную ошибку RPC в `check_failed` для всех строк. Этому соответствует
  текст «Служба не смогла выполнить проверку». Он не доказывает остановку службы или VPN. В состоянии подключения
  пробы возвращают снимок без реальных измерений, что согласуется с наличием строк во втором отчете.
- Исходное исключение не попадает в экспорт: провайдеры журналирования IPC очищены, обработчик проверки не пишет
  исключение в журнал приложения, клиент сохраняет только обобщенную причину. Назвать конкретную упавшую пробу по
  этим файлам нельзя. «До и после VPN — служба не ответила» также является обобщением ошибок RPC/контракта.
- Ручной запуск в `Gateway.ConfirmAsync` допускает две пробы с заданным таймаутом подключения. Автоматическая попытка
  в `Gateway.ReconnectAsync` после `RestartAsync` допускает одну пробу с таймаутом по умолчанию 10 секунд. Затем при
  отказе начинается следующая попытка с перезапуском ядер. Код уже учитывает случай, когда первая проба на раздаче
  телефона не проходит, а вторая успешна, но в автоматическом подтверждении этого повтора нет.
- Автоматический повтор использует прежний набор адресов и режим привязки; ручное включение заново разрешает имя
  и после полного отключения без сохраненного блока выполняет предварительную проверку. Сторож измеряет путь через
  отдельный вход Xray и не проверяет весь путь
  через TUN и системный DNS. Эти различия требуют проверки, но не устанавливают причину данного обрыва.
- Фоновая проверка выходного IP прекращается после двух неудачных попыток. Страница «Проверка» и новое подключение
  запускают дополнительный запрос; поэтому IP может появиться после действий пользователя. Полученный свежий адрес
  интерфейс уже умеет отобразить без смены страницы — дефект находится в продолжении запросов службы.
- Импорт sing-box теряет `mode` XHTTP на C#, Kotlin и Swift. Это отдельный подтвержденный дефект разбора, но нет
  доказательства, что именно он объясняет отказы из присланных отчетов.

## Изменения реализации

- [x] Изолировать ошибки IP, IPv6, DNS и обнаружения других VPN. Независимые результаты и известные состояния
  службы, ядра и блока сохраняются; неудачная проба получает `probe_failed`, устаревшая сессия — `session_changed`.
  «До и после VPN» также сохраняет частичный результат; отсутствие измерения IPv6 не означает «IPv6 закрыт».
- [x] Записывать операцию, тип исключения, HRESULT и доступные коды RPC/socket/HTTP. Текст исключения, стек, адреса,
  ссылки и секреты не записываются; отмененный пользователем запрос не становится ошибкой.
- [x] Дать автоматическому подтверждению вторую пробу с настроенным таймаутом и оставшимся сроком политики повтора.
  Между пробами проверяется актуальность сессии. Ошибка остановки или неожиданное завершение фоновой задачи
  не оставляет бессрочную надпись «Переподключение»; включенная блокировка сохраняется.
- [x] Продолжать получение IP с паузами 3, 6, 12, 24 и затем 30 секунд до измерения в актуальном подключении.
  DNS и IPv6 выполняются независимо; пауза, потеря сети, новая сессия и остановка службы не позволяют публиковать
  старый результат. Выключенная пользователем автоматическая проверка не включается скрытно.
- [x] Различать причины неудачного замера в списке и показывать его время в подсказке. Главный экран учитывает отказ
  нового замера вместо сообщения «пинг проверен». Безопасный журнал сохраняет причины обеих HTTP-попыток и номер
  профиля в конкретном запросе IPC; этот номер не обязательно совпадает со строкой отсортированного списка.
- [x] Сохранять `mode` при импорте XHTTP из sing-box на трех платформах. Расширенные параметры `extra` пока не
  реализованы; профили не удаляются из списка и не объявляются полностью совместимыми только из-за этой правки.

## Проверка и оставшиеся вопросы

- [x] Добавить регрессионные проверки изоляции ошибок, отмены старых измерений, фонового получения IP,
  повторного подтверждения связи и честного отображения результатов. Автоматические прогоны не заменяют приемку владельца.
- [ ] Пройти [план M4](../../testing/macos-reconnect-diagnostics.md): холодный запуск → XHTTP → TCP → «Проверка»,
  автоматическое восстановление, IP без навигации, частичные результаты, повторный замер профилей и регрессия
  четырех уже принятых исправлений.
- [ ] Если внешний обрыв повторится, сопоставить новый безопасный журнал с временем ошибки и сравнением одного
  профиля в той же сети. Ошибка TLS контрольной HTTPS-пробы сама по себе не означает неправильные ключи REALITY.

Первопричина конкретного обрыва пока не установлена. При исправлении автоматического восстановления нельзя
снимать включенный пользователем Kill Switch между попытками. Новый выпуск и изменение серверной конфигурации
этим разбором не запускаются.
