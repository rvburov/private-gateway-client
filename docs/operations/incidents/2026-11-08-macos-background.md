## Исправление интерфейса

Окно различает отсутствие установки, подтвержденный запрет, установленную недоступную службу и неизвестный ответ.
На macOS 13+ Infrastructure читает `SMAppService.statusForLegacyPlist(at:)` для своего plist. Только
`requiresApproval` подтверждает запрет. Ошибка API не превращается в «служба не установлена».

При запрете: «Разрешите фоновую работу службы», объяснение с именем PrivateGatewayService,
«Открыть настройки macOS» (штатный `openSystemSettingsLoginItems`) и «Проверить снова». Установщик не предлагается, в том числе при переходе из пользовательской службы прокси в VPN (PGC-SVC-004).
Проверка снова ищет IPC и не подключает VPN. Разрешение само по себе не доказывает связь: нужен ответ службы.
Первоначальный Off интерфейса тоже не доказывает ее восстановление.

Служба регистрируется для запуска с ОС при установке с правами администратора. Фоновое разрешение macOS,
запуск окна при входе и подключение VPN при запуске — разные настройки. Запрет пользователя не отменяется программно.

## Автоматические проверки и ограничения

Unit/UI проверяют ответы разрешения, отсутствие установщика при запрете, переход в настройки, повторный поиск
без подключения VPN, неизвестный ответ и связь Kill Switch со строгим режимом. В CI macOS существующий тест установки
launchd дополнительно читает состояние настоящей тестовой службы через SMAppService. Сам запрет разрешения в UI-тестах
моделируется; системное окно настроек автоматически не переключается.

Существующие CI-тесты запускают TUN, PF, системный DNS и HTTP по имени на локальном стенде. Они не являются тестом
перезагрузки физического M4, браузера Safari или совместимости с пользовательскими VPN-профилями.

Проверка изменения 2026-11-08 в отдельной рабочей папке на M4, без установки службы и изменения сети:

- Полное решение: **2433 всего / 2310 успешно / 0 ошибок / 123 пропуска**. Пропуски — другие ОС и проверки,
  которым нужны root и изменение системной сети; они выполняются отдельно в CI.
- Шесть временных поломок обнаружены тестами: сохранение StrictMode при выключенном Kill Switch;
  потеря RequiresApproval; предложение установки при запрете; принятие начального Off за ответ службы;
  повторная установка запрещенной службы из приветствия; пропуск проверки разрешения при переходе из прокси в VPN.
  После каждого прогона код восстановлен.
- Настоящий вызов `MacServiceAccess.Read()` из временного процесса обычного пользователя вернул `Installed`
  для текущей разрешенной службы. Настройки ОС не открывались и не изменялись. Отказ разрешения проверен имитацией,
  а не переключением фонового разрешения на машине пользователя.
