# DNS настольного клиента: настройка, правила и результат пробы

Дата: 2026-11-04. Основа: `master` клиента `b60247d43dbb6a0046798978fc8c8b73f5712957`.
Предыдущий разбор `2488269` подтвержден по свежему коду. Изменяется только `private-gateway-client`.

## Наблюдение и причина неоднозначности

Пользователь видит несколько DNS-адресов на браузерном тесте и одновременно зеленую DNS-плитку клиента.
Это разные сведения: список браузерного теста описывает рекурсивные резолверы, обратившиеся к авторитетному DNS,
а клиент собирает конфигурацию ядра и проверяет конкретную возможность прямого DNS-запроса.

В исходной реализации:

- Значение `DnsChoice.Profile` выбирало Cloudflare DoH по умолчанию; отдельного DNS в `ServerDefinition` не было.
  Надпись «Из профиля» обещала источник настройки, которого код не использовал.
- `DnsProbe` отправлял корневой запрос NS через внешний адаптер по IPv4 UDP/53. `false` объединял отсутствие ответа
  и сетевые ошибки; `CheckDnsAsync` мог вернуть диагностический успех и сбросить прежнее предупреждение.
- Главная иногда выводила причину DNS-предупреждения из выбранных сейчас настроек вместо параметров действующей сессии.
- Отчет не сводил эти разные уровни DNS в один раздел с явными границами измерения.

Количество DNS-IP, геолокация и различие ASN сами по себе не устанавливают обход VPN. Публичный DNS может
использовать несколько исходящих адресов. FakeDNS не отменяет внешнего разрешения имен, а браузерный DoH
может обращаться к другому резолверу внутри самого VPN. Настройки DNS адаптера/TUN также не являются списком
внешних резолверов браузерного теста.

## Контракт исправления

1. Настольный пункт по умолчанию называет Cloudflare. Сохраненное значение `Profile`, выбор Quad9 и свой DNS
   остаются совместимыми; реальная конфигурация и маршруты не меняются ради нового названия.
2. Выбранные настройки, снимок состояния защиты службы и диагностический результат показываются отдельно.
   Изменение выбора в окне не доказывает его применение к уже действующему подключению.
3. Проверенный ответ прямой пробы дает `dns_open` и предупреждение о доступном обходе. Отсутствие ответа —
   `dns_no_answer`, недоступный замер — `dns_unavailable`. Неизвестность не заменяет состояние примененных правил
   и не стирает прежнее измеренное открытие пути. Отмена остается отменой.
4. Старый ответ после смены сессии, сети, параметров или паузы не меняет новый статус и не обвиняет новую сессию.
5. Отчет описывает тип своего DNS и число выбранных исключений без адресов, путей, доменов и секретных URL.
   Внешние браузерные резолверы дополнительно не собираются. Для старой/отсутствующей службы и имитации нет
   выдуманного подтверждения пробы.

Точная область пробы — IPv4 UDP/53 на выбранном внешнем адаптере. Не измеряются все DoH/DoT-пути, IPv6 DNS,
браузерные переопределения и внешние рекурсивные IP. Отсутствие ответа не равнозначно доказанной блокировке.

В режиме «Только прокси» ядро обслуживает использующие его соединения; DNS всей ОС не перехватывается.
Частный пользовательский DNS и прямые исключения остаются осознанными настройками и требуют отдельной оценки.

## Проверки

Автоматические регрессии покрывают сохранение выбора DNS, соответствие подписи реальному Cloudflare-конфигу,
ответ/тишину/недоступность/отмену, сохранение прежнего предупреждения, актуальность сессии и сети, VPN/прокси,
неизвестные и старые результаты, безопасный отчет и компоновку RU/EN. Локальная Release-сборка и проверка
форматирования прошли без ошибок. Полные наборы: Unit — 1035 успешно / 6 пропусков; Architecture — 19 / 0;
UI — 418 / 0; Network — 608 / 113. Ошибок нет; пропуски относятся к ОС, привилегиям и отсутствующим возможностям
облачной машины, а не считаются успешными тестами. Все 18 компилируемых мутантов пойманы; исходники после них
точно восстановлены, повторные сборки и проверки прошли. CI проверяет платформенные сценарии отдельно.

На компьютере пользователя нужно отдельно проверить [раздел 12 чеклиста Windows](../../testing/windows-check.md#12-dns-настройка-политика-и-измерение-2026-11-04).
Локальный стенд и CI не заменяют проверку его браузера, реальных исключений и маршрутов.

Серверный репозиторий, DNS-маршрутизация, настройки браузеров и workflows этой задачей не меняются.
