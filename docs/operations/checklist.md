# Релизный чеклист

Один путь от `master` до стабильного выпуска у всех. Как устроена сборка выпуска, подпись и раскатка —
[docs/architecture/release.md](../architecture/release.md); что делать, когда с выпуском что-то не так, —
[support.md](support.md). Пункт не выполнен — выпуска нет: «потом проверим» здесь не бывает.

## 1. Перед тегом

- [ ] `master` на коммите выпуска, проверка CI на нем зеленая целиком: «Сборка и тесты» на трех ОС, «Стиль и формат»,
      «Другие процессоры» (Linux ARM, Mac с Intel), «Секреты в репозитории», Android и «Android (эмулятор)». В сводке заданий — ни одного пропуска вне
      `desktop/tests/allowed-skips.json`.
- [ ] Долгий прогон (`soak.yml`) — ночные запуски на `master` зеленые. На коммите тега его гоняет сам выпуск (задание
      «Долгий прогон» в `release.yml`, 30 минут на режим): режим прокси на трех ОС, VPN на Linux и Windows, утечек нет,
      ресурсы не растут. Красный — выпуск не публикуется.
- [ ] `publish.yml` на коммите выпуска зеленый на трех ОС: пакеты ставятся и удаляются, смоук выпуска проходит.
- [ ] Открытых пунктов о сбоях и утечках в ROADMAP (README, этапы 3, 4 и 11) нет — или у каждого записано, почему он не
      держит выпуск.
- [ ] Проверка пользователем на своих машинах по [windows-check.md](../testing/windows-check.md) и
      [android-check.md](../testing/android-check.md) для того, что в CI не проверить (настоящая сеть, TUN без узкого
      маршрута, телефон): итоги — пунктами в ROADMAP. Для беты достаточно Windows или Linux; для стабильного — все ОС
      выпуска.
- [ ] Лицензии: `shared/licenses/components.json` и `shared/licenses/android.json` покрывают все пакеты — иначе выпуск и
      APK не собираются сами; новые ядра и шрифты — со строкой и текстом лицензии.
- [ ] Секреты: `gitleaks` по истории с прошлого тега чистый; в журналах и отчете проверки — `SecretMasker`.
- [ ] Ключ подписи обновлений: секрет `UPDATE_SIGNING_KEY` есть, его открытый ключ — в `shared/update/keys`. Без них
      выпуск собирается неподписанным, и служба его не поставит (так и должно быть до первого ключа).
- [ ] Версия: одна на все платформы — `<Version>` в `Directory.Build.props` (десктоп, Android `versionName`, iOS);
      `scripts/release.sh` ставит в него номер выпуска сам, `versionCode` Android считается из номера.
- [ ] История: в `CHANGELOG.md` пункты из `## [Не выпущено]` перенесены в новую секцию `## [X.Y.Z]` — коротко, для
      людей, по шаблону в начале файла, без «@слов»; из нее собираются «Что нового» на странице выпуска и до трех строк
      карточки обновления в окне. Секции нет — выпуска нет. Текст страницы заранее: `scripts/release-notes.sh X.Y.Z`.

## 2. Бета

- [ ] Бета (номер с суффиксом) — тегом вручную: `git tag -a vX.Y.Z-beta.N -m "Private Gateway X.Y.Z-beta.N"` и
      `git push origin vX.Y.Z-beta.N` на проверенном коммите `master`; секция в `CHANGELOG.md` — `## [X.Y.Z-beta.N]`.
      `scripts/release.sh` выпускает только X.Y.Z, как в SmartBase. `release.yml` сам сверяет версию и секцию, SHA,
      принадлежность `master`, зеленую CI этого SHA и гоняет долгий прогон до сборки; при отказе — исправить причину и
      повторить запуск тега («Re-run»).
- [ ] `release.yml` зеленый, выпуск на GitHub помечен предварительным, в нем файлы трех ОС, `SHA256SUMS`, `update.json` и
      (с ключом) `update.json.sig`.
- [ ] Загрузка сверяется: `sha256sum -c SHA256SUMS` в папке скачанных файлов.
- [ ] Установка с нуля на чистой машине каждой ОС, затем обновление с прошлого выпуска через «О программе» →
      «Проверить» (канал «Бета»), затем «Откатить на …»: защита после каждого шага держится, блок при обрыве не
      выпускает трафик, пока служба меняется.
- [ ] Бета живет не меньше недели без сообщений о сбоях из раздела «Серьезность» [support.md](support.md) уровней 1 и 2.

## 3. Стабильный выпуск

- [ ] `scripts/release.sh X.Y.Z` в основной папке на `master` (сначала `--dry-run`): проверки, план, «Выпустить? [y/N]»,
      затем коммит `release: vX.Y.Z` с датой секции, аннотированный тег и отправка. Дальше — GitHub (около двух часов).
- [ ] `release.yml` зеленый; раскатка — 20 %; на странице выпуска — «Что нового» из секции, таблица установки, первый
      запуск, никаких участников в «Contributors».
- [ ] Сутки без сообщений уровней 1–2 → `release-rollout.yml`: тег и доля 50 %. Еще сутки → 100 %.

## 4. После выпуска

- [ ] `<Version>` в `Directory.Build.props` (версия отладочных сборок) — следующая; в ROADMAP — отметка о выпуске с датой.
- [ ] Сообщения пользователей — по [support.md](support.md); найденное — пунктами ROADMAP.
- [ ] Подписи кода Windows и macOS — пока в разделе ROADMAP «Отложено»: в заметках выпуска сказано, как поставить
      неподписанную программу.
