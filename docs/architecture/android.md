# Android

Приложение для Android 9+ (minSdk 28, targetSdk 36): Kotlin, Jetpack Compose, туннель — системный VPN Android
(`VpnService`), ядро — Xray-core внутри процесса приложения (libXray). Экран тот же, что у десктопа: токены, тексты и
правила разбора общие (доски 25–26 макета).

## Где что лежит

```
android/
├── settings.gradle.kts      — модуль app; core и build-logic — составные сборки
├── gradle/libs.versions.toml — версии библиотек и плагинов (как Directory.Packages.props у десктопа)
├── libxray.version          — закрепленный коммит XTLS/libXray (scripts/get-libxray.sh)
├── core/                    — общий модуль на чистом Kotlin, без Android API
├── build-logic/             — плагин сборки: тема и тексты из shared/specifications
└── app/                     — приложение: Compose, VpnService, хранилище
```

| Модуль | Что внутри | Сборка |
| --- | --- | --- |
| `core` | разбор ссылок и подписок (`LinkParser`, `ImportParser`: ссылки, base64, sing-box JSON, Clash YAML), ссылка из сервера (`LinkWriter`), конфиг Xray (`XrayConfig`), план карты туннеля (`TunPlan`), DNS ядра до туннеля и за сменой сети (`CoreDns`, `CoreDnsFollower`), подписи сервера (`ServerFacts`), подписки (`SubscriptionMerge`, `SubscriptionDownloader`), настройки туннеля (`TunnelSettings`), QR-код (`QrCode`, ZXing), `SecretMasker`, формы чисел (`Plural`) | `android/gradlew -p android/core test` — нужен только JDK 17+, без SDK Android и репозитория Google |
| `build-logic` | плагин `privategateway.shared-resources`: задачи `generatePgTheme` и `generatePgResources` | `android/gradlew -p android/build-logic test` — так же без SDK |
| `app` | окно, служба VPN, хранилище, тесты Robolectric | `android/gradlew -p android :app:assembleDebug :app:testDebugUnitTest :app:lintDebug` — нужны SDK Android, NDK для ядра и `scripts/get-libxray.sh` |

Правила те же, что у десктопа, и держатся одинаковыми тестами на общих данных: эталоны `shared/testdata` (разбор), те же
случаи подписей, маскирования и форм чисел, что в тестах .NET.

## Тема, иконки и тексты

Сгенерированных файлов в git нет — плагин `build-logic` собирает их при каждой сборке, и разойтись с источником они не
могут:

- `Tokens.kt` — из `shared/specifications/design-tokens.json`, имена как у `Tokens.axaml` десктопа: `PgColor.Bg.Window`,
  `PgState.Connected.Ring`, `PgType.H1` (TextStyle с размером, начертанием, трекингом и высотой строки в em),
  `PgSpace.Card`, `PgRadius.Card`, `PgShadow.Card`, `PgLayout.Island.Height`. Тест сверяет каждый цвет с `Tokens.axaml`.
- `Icons.kt` — контуры 24×24 из `desktop/src/Client.UI/Themes/Icons.axaml` (`Icon.Nav.Home` → `PgIcons.NavHome`),
  рисуются линией (`PgIcon`).
- `strings.xml` — из `shared/specifications/localization`: `values/` — английский (язык по умолчанию: телефон на любом
  языке, кроме русского), `values-ru/` — русский. Ключ `status.connected.title` → `R.string.status_connected_title`
  («.» и «-» → «_»), подстановка `{0}` → `%1$s`. Два ключа с одним именем ресурса, разные ключи RU и EN — ошибка сборки.
  Тест читает каждый текст обратно через ресурсы Android. Тексты только для телефона — ключи `android.*`.
- иконка запуска (адаптивная, с одноцветным слоем Android 13+) и значок уведомления — щит из `Icons.axaml` цветом
  «Защищено».

Язык приложения — системный или выбранный для приложения в настройках Android 13+ (список языков — `xml/pg_locales.xml`).

## Туннель

`GatewayVpnService` (`VpnService`, служба переднего плана типа specialUse с подтипом vpn):

1. Окно спрашивает разрешение Android на VPN (`VpnService.prepare` — системное окно один раз) и на уведомления (Android
   13+), затем запускает службу. «Постоянная VPN» запускает ее сама (действие `android.net.VpnService`,
   `SUPPORTS_ALWAYS_ON`).
2. Служба берет выбранный сервер (другой сам не выбирается), настройки туннеля (DNS, IPv6 через сервер, локальная сеть —
   DataStore) и DNS текущей сети — до того как сетью станет туннель.
3. Карта туннеля по `TunPlan`: адрес `172.19.0.1/30`, маршрут `0.0.0.0/0` — весь IPv4, DNS `172.19.0.2` — внутри
   туннеля, его запросы ядро отвечает через сервер (правило «порт 53 → выход DNS» в конфиге). IPv6: без настройки «IPv6
   через сервер» у туннеля нет адреса и маршрута IPv6 — тогда Android сам закрывает IPv6 всем программам, и они сразу
   уходят на IPv4. Сеть под туннелем считается платной, только если платная она сама (`setMetered(false)`).
4. Ядро — libXray: конфиг Xray с входом `tun` по дескриптору карты (`env.xray.tun.fd`); сокеты ядра выводятся из
   туннеля (`protect` через `registerDialerController`), адрес сервера ядро находит через DNS сети (`setDNS`, защищенный
   сокет). Xray читает свою копию дескриптора; карту закрывает приложение — после остановки ядра. Контроллер сокетов —
   один на процесс (Xray хранит каждый до конца процесса и снять не дает), за ним меняется только работающая служба.
5. Сеть телефона меняется (Wi-Fi ↔ мобильная, новый DNS): служба следит за лучшей сетью с интернетом, кроме VPN (Android
   12+ `registerBestMatchingNetworkCallback`, раньше `requestNetwork`), и передает ядру DNS новой сети (`CoreDnsFollower`):
   DNS прежней сети из новой обычно недоступен, и сервер по имени перестал бы находиться. Сеть под туннелем Android берет
   сам — сеть по умолчанию.
6. Состояние — `TunnelMonitor` (общий поток службы и окна): Выключено, Подключение, Защищено, Отключение, Ошибка с кодом.
   Под защитой служба передает и то, что Android сообщает только работающему VPN (Android 10+): включены ли «Постоянная
   VPN» и «Блокировать подключения без VPN».
7. Уведомление туннеля — состояние, сервер и «Отключить» (канал «Защита», без звука). Защита не включилась — уведомление
   «Защита не работает» с причиной в канале «Сбои защиты» (со звуком): запуск «Постоянной VPN» в окне не виден. Отзыв VPN
   (другая программа включила свой VPN, пользователь отключил в настройках) — отключение.
8. Остановка гасит службу по номеру своего запуска (`stopSelfResult`): подключение, пришедшее после «Отключить», службу
   не теряет. Служба уничтожена посреди подключения — подключение само снимает туннель и ядро.
9. Переподключение (другой сервер, новые настройки) — без окна утечки: новая карта поднимается, пока прежняя держит
   трафик (Android заменяет одну другой), и только потом останавливается прежнее ядро; до запуска нового пакеты ждут в
   карте, а не уходят мимо туннеля.

Коды ошибок — те же, что у десктопа (`docs/architecture/errors.md`): `PGC-SVC-002` — ядро не запустилось,
`PGC-SVC-003` — сервер не выбран или удален, `PGC-SVC-005` — ядро не умеет этот сервер (Hysteria2 и TUIC: на Android
второго ядра нет), `PGC-NET-010` — Android не дал поднять VPN (место занял VPN другой программы или разрешение отозвано).
Текст ошибки ядра пишется в журнал Android только через `SecretMasker`.

Блок при обрыве на Android — системный: «Постоянная VPN» и «Блокировать подключения без VPN» включает только пользователь
в настройках VPN телефона; «Настройки» открывают их кнопкой, чип «Блок при обрыве» показывает то, что сообщил Android.

## Хранение

- Серверы — Room (`private-gateway.db`): открыто — только подписи списка (название, страна, протокол, защита, транспорт,
  порт); сам сервер — ссылка с адресом и ключом — запечатан AES-256-GCM ключом из Android Keystore (`KeystoreSecretBox`,
  ключ `pg-servers-v1` не покидает хранилище устройства). Не открылся (ключ утерян после сброса) — сервер виден в списке,
  удалить можно, подключиться нельзя.
- Дубль — тот же сервер под другим названием: та же ссылка без имени и флага.
- Настройки — DataStore: выбранный сервер. Первый импорт сам выбирает первый новый сервер, дальше выбор меняет только
  пользователь. Выбранный удален, другие остались — кнопка-щит ведет к списку.
- Добавления в хранилище идут по одному (двойное нажатие не дает дублей); текст импорта живет в модели окна, а не в
  сохраненном состоянии окна (большой конфиг уронил бы процесс, ключи попали бы в системный процесс).
- Резервная копия Android и перенос на другое устройство выключены (`pg_data_extraction.xml`): без ключа Keystore этого
  устройства копия бесполезна, а открытым текстом ее отдавать нельзя.

## Ядро libXray

`scripts/get-libxray.sh` собирает `android/app/libs/libXray.aar` (в git не хранится) из исходников коммита
`android/libxray.version` через gomobile (версия gomobile и gobind — из go.mod libXray, суммы модулей сверяет go.sum),
для всех ABI, с минимальным API 28 и страницами 16 КБ. Нужны go и Android NDK. Версия Xray-core на Android — та, что в
go.mod этого коммита libXray (вход `tun` по дескриптору есть только в новых Xray); на десктопе ядро свое
(`shared/cores/xray.version`).

Один рантайм Go на процесс: других библиотек Go в приложении нет и быть не должно (предупреждение libXray).

## Тесты

- `core` — JUnit 5: разбор на всех эталонах `shared/testdata` и обратно через `LinkWriter`, импорт sing-box и Clash,
  конфиг Xray, план туннеля и DNS ядра, подписки, настройки туннеля, QR-код (те же случаи, что у десктопа, и кадр камеры),
  подписи, маскирование, формы чисел.
- `build-logic` — JUnit 5 на настоящих файлах репозитория: цвета совпадают с `Tokens.axaml`, все тексты RU и EN читаются
  обратно по правилам Android, экранирование, повтор имен.
- `app` — Robolectric (без устройства, Android 15): хранилище (каждый эталон возвращается тем же, адрес и ключи только
  запечатанными, дубли, одновременные добавления, незапечатанное), настройки, тексты из ресурсов на двух языках и язык
  форм чисел, чипы защиты по состояниям, кнопка-щит, экраны Compose (главная в каждом состоянии, серверы, добавление,
  островок), модель окна.
- Android Lint — его ошибки роняют CI.

Не проверено тестами CI: настоящий туннель на устройстве или эмуляторе, Keystore, «Постоянная VPN», смена сети и сон —
пункт 9.4 (эмулятор в CI) и проверка на телефоне.
