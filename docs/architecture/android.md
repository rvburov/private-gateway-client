# Android

Приложение для Android 9+ (minSdk 28, targetSdk 36): Kotlin, Jetpack Compose, туннель — системный VPN Android
(`VpnService`), ядро — Xray-core внутри процесса приложения (libXray). Экран тот же, что у десктопа: токены, тексты и
правила разбора общие (доски 25–26 макета).

## Где что лежит

```
android/
├── settings.gradle.kts      — модуль app; core и build-logic — составные сборки
├── gradle/libs.versions.toml — версии библиотек и плагинов (как Directory.Packages.props у десктопа)
├── libxray.version          — закрепленный коммит XTLS/libXray (scripts/get-libxray.sh)
├── core/                    — общий модуль на чистом Kotlin, без Android API
├── build-logic/             — плагин сборки: тема и тексты из shared/specifications
└── app/                     — приложение: Compose, VpnService, хранилище
```

| Модуль | Что внутри | Сборка |
| --- | --- | --- |
| `core` | разбор ссылок и подписок (`LinkParser`, `ImportParser`: ссылки, base64, sing-box JSON, Clash YAML), ссылка из сервера (`LinkWriter`), конфиг Xray (`XrayConfig`), план карты туннеля (`TunPlan`), DNS ядра до туннеля и за сменой сети (`CoreDns`, `CoreDnsFollower`), подписи сервера (`ServerFacts`), список серверов — поиск, вкладки, группы, порядок (`ServerList`), быстрая смена (`QuickSwitch`), свое название (`ServerNames`), задержка (`Latency`, замер через libXray — `PingBatch`), подписки (`SubscriptionMerge`, `SubscriptionDownloader`), настройки туннеля (`TunnelSettings`: свой DNS — только IP или DoH по IP, `IpAddress`; DNS в локальной сети идет мимо туннеля — `lanDns`, `PrivateNetwork`; что требует переподключения — `needsReconnect`), QR-код (`QrCode` — картинка, `QrScanner` — кадр камеры, `QrImageSize` — большие фото до 8 Мп, ZXing), `SecretMasker`, формы чисел (`Plural`) | `android/gradlew -p android/core test` — нужен только JDK 17+, без SDK Android и репозитория Google |
| `build-logic` | плагин `privategateway.shared-resources`: задачи `generatePgTheme` и `generatePgResources` | `android/gradlew -p android/build-logic test` — так же без SDK |
| `app` | окно, служба VPN, хранилище, тесты Robolectric | `android/gradlew -p android :app:assembleDebug :app:testDebugUnitTest :app:lintDebug` — нужны SDK Android, NDK для ядра и `scripts/get-libxray.sh` |

Правила те же, что у десктопа, и держатся одинаковыми тестами на общих данных: эталоны `shared/testdata` (разбор), те же
случаи подписей, маскирования и форм чисел, что в тестах .NET.

## Тема, иконки и тексты

Сгенерированных файлов в git нет — плагин `build-logic` собирает их при каждой сборке, и разойтись с источником они не
могут:

- `Tokens.kt` — из `shared/specifications/design-tokens.json`, имена как у `Tokens.axaml` десктопа: `PgColor.Bg.Window`,
  `PgState.Connected.Ring`, `PgType.H1` (TextStyle с размером, начертанием, трекингом и высотой строки в em),
  `PgSpace.Card`, `PgRadius.Card`, `PgShadow.Card`, `PgLayout.Island.Height`. Тест сверяет каждый цвет с `Tokens.axaml`.
- `Icons.kt` — контуры 24×24 из `desktop/src/Client.UI/Themes/Icons.axaml` (`Icon.Nav.Home` → `PgIcons.NavHome`),
  рисуются линией (`PgIcon`).
- `strings.xml` — из `shared/specifications/localization`: `values/` — английский (язык по умолчанию: телефон на любом
  языке, кроме русского), `values-ru/` — русский. Ключ `status.connected.title` → `R.string.status_connected_title`
  («.» и «-» → «_»), подстановка `{0}` → `%1$s`. Два ключа с одним именем ресурса, разные ключи RU и EN — ошибка сборки.
  Тест читает каждый текст обратно через ресурсы Android. Тексты только для телефона — ключи `android.*`.
- иконка запуска (адаптивная, с одноцветным слоем Android 13+) и значок уведомления — щит из `Icons.axaml` цветом
  «Защищено».

Язык приложения — системный или выбранный для приложения в настройках Android 13+ (список языков — `xml/pg_locales.xml`).

## Туннель

`GatewayVpnService` (`VpnService`, служба переднего плана типа specialUse с подтипом vpn):

1. Окно спрашивает разрешение Android на VPN (`VpnService.prepare` — системное окно один раз) и на уведомления (Android
   13+), затем запускает службу. «Постоянная VPN» запускает ее сама (действие `android.net.VpnService`,
   `SUPPORTS_ALWAYS_ON`).
2. Служба берет выбранный сервер (другой сам не выбирается), настройки туннеля (DNS, IPv6 через сервер, локальная сеть —
   DataStore) и DNS текущей сети — до того как сетью станет туннель.
3. Карта туннеля по `TunPlan`: адрес `172.19.0.1/30`, маршрут `0.0.0.0/0` — весь IPv4, DNS `172.19.0.2` — внутри
   туннеля, его запросы ядро отвечает через сервер (правило «порт 53 → выход DNS» в конфиге). IPv6: без настройки «IPv6
   через сервер» у туннеля нет адреса и маршрута IPv6 — тогда Android сам закрывает IPv6 всем программам, и они сразу
   уходят на IPv4. Сеть под туннелем считается платной, только если платная она сама (`setMetered(false)`).
4. Ядро — libXray: конфиг Xray с входом `tun` по дескриптору карты (`env.xray.tun.fd`); сокеты ядра выводятся из
   туннеля (`protect` через `registerDialerController`), адрес сервера ядро находит через DNS сети (`setDNS`, защищенный
   сокет). Xray читает свою копию дескриптора; карту закрывает приложение — после остановки ядра. Контроллер сокетов —
   один на процесс (Xray хранит каждый до конца процесса и снять не дает), за ним меняется только работающая служба.
5. Сеть телефона меняется (Wi-Fi ↔ мобильная, новый DNS): служба следит за лучшей сетью с интернетом, кроме VPN (Android
   12+ `registerBestMatchingNetworkCallback`, раньше `requestNetwork`), и передает ядру DNS новой сети (`CoreDnsFollower`):
   DNS прежней сети из новой обычно недоступен, и сервер по имени перестал бы находиться. Сеть под туннелем Android берет
   сам — сеть по умолчанию.
6. Состояние — `TunnelMonitor` (общий поток службы и окна; типы — `core/vpn/TunnelStatus.kt`): Выключено, Подключение,
   Защищено, Переподключение (с номером попытки), Отключение, Ошибка с кодом.
   Под защитой служба передает и то, что Android сообщает только работающему VPN (Android 10+): включены ли «Постоянная
   VPN» и «Блокировать подключения без VPN».
7. Уведомление туннеля (доска 26, канал «Защита», без звука) — «IP скрыт · сервер», шифруется ли трафик, «в сети» с
   таймером, «Отключить» и «Сменить сервер» (открывает «Серверы»); во время переподключения — «Переподключение…» и сервер.
   Остальные уведомления — раздел «Уведомления» ниже. Отзыв VPN (другая программа включила свой VPN, пользователь отключил
   в настройках) — отключение.
8. Остановка гасит службу по номеру своего запуска (`stopSelfResult`): подключение, пришедшее после «Отключить», службу
   не теряет. Служба уничтожена посреди подключения — подключение само снимает туннель и ядро.
9. Плитка в шторке (`GatewayTileService`, доска 26) включает и выключает VPN без окна: к выбранному серверу и только
   после разблокировки экрана; сервера нет или нет разрешения на VPN — открывает окно (решение 415).
10. Переподключение (другой сервер, новые настройки) — без окна утечки: новая карта поднимается, пока прежняя держит
   трафик (Android заменяет одну другой), и только потом останавливается прежнее ядро; до запуска нового пакеты ждут в
   карте, а не уходят мимо туннеля.
11. Связь с сервером (`core/vpn/TunnelGuard.kt` — `WatchLoopAsync` и `ReconnectLoopAsync` десктопа, решение 441): пока
   защита включена, служба пробует связь — запрос HEAD к `cp.cloudflare.com/generate_204` из процесса приложения, то есть
   через туннель (приложение из своего VPN не исключено), срок 10 с; сразу после подключения и дальше раз в минуту. Одна
   неудача бывает и у живого сервера — вторая проба сразу; две подряд — обрыв: «Переподключение» к тому же серверу (другой
   сам не выбирается). Попытка — тот же запуск карты и ядра (путь без окна утечки) и проба; паузы 1, 2, 4… до 60 с.
   Политика — «Настройки» → «Переподключение»: «Экспоненц. до 60 с» (пока пользователь не выключит), «До 5 минут»,
   «Не повторять»; кончилась — «Ошибка» с кодом `PGC-NET-001` или кодом последней неудачи; сервер удален, VPN занят
   другой программой, ядро не берется за сервер — «Ошибка» сразу. Сеть сменилась (Wi-Fi ↔ мобильная) или телефон вышел из
   глубокого сна (Doze) — проба или попытка сразу. Все это время карта туннеля держит трафик: он ждет, а не идет мимо.

Коды ошибок — те же, что у десктопа (`docs/architecture/errors.md`): `PGC-NET-001` — сервер не отвечает (переподключение
сдалось), `PGC-SVC-002` — ядро не запустилось,
`PGC-SVC-003` — сервер не выбран или удален, `PGC-SVC-005` — ядро не умеет этот сервер (Hysteria2 и TUIC: на Android
второго ядра нет), `PGC-NET-010` — Android не дал поднять VPN (место занял VPN другой программы или разрешение отозвано).
Текст ошибки ядра пишется в журнал Android только через `SecretMasker`.

Настройки туннеля — «Настройки» → «Защита и утечки» (решения 412–414): DNS в туннеле (из профиля, DoH Cloudflare, DoH
Quad9, свой адрес — только IP или DoH по IP), «Приоритет адресов» («Только IPv4» — IPv6 закрыт Android, «Предпочитать
IPv4» — IPv6 через сервер), «Разрешить локальную сеть». Под защитой изменение само переподключает туннель через 0,7 с
тишины — путем без окна утечки; то, что ядра не меняет, переподключения не требует.

Блок при обрыве на Android — системный: «Постоянная VPN» и «Блокировать подключения без VPN» включает только пользователь
в настройках VPN телефона; «Настройки» открывают их кнопкой, чип «Блок при обрыве» показывает то, что сообщил Android.

«Постоянная VPN» и блок без VPN (решение 445):

- Android сообщает флаги только работающему туннелю (Android 10+); служба запоминает их при каждом подключении
  (DataStore). Карточка «VPN в настройках Android» показывает оба флага («вкл», «выкл», «неизвестно») и откуда они: «Так
  сейчас сообщает Android» под защитой, «при последнем подключении» без нее, «появятся после подключения» — если Android
  их еще не сообщал (`SystemVpnView`).
- Закрыта ли сеть приложению самим Android, приложение узнает сразу, без подключения: сеть по умолчанию и ее блокировка
  (`NetworkAccess`, `onBlockedStatusChanged`, Android 10+). Без туннеля при «Блокировать подключения без VPN» главная
  говорит «Интернет закрыт Android: без VPN подключения блокируются», чипы — как у сработавшего блока десктопа (трафик
  остановлен, DNS и IPv6 — утечки нет, блок — сработал), «Ошибка» — «трафик заблокирован», а не «идет напрямую».
- Замер задержки при закрытой сети не идет («Задержка не меряется: Android закрыл интернет без VPN»): иначе все серверы
  «не ответили» бы из-за блока; закрылась во время порции — порция отбрасывается.
- «Постоянная VPN» запускает службу сама; подключение — к выбранному серверу, без него — «Ошибка» с кодом и уведомление.

## Уведомления

Доска 22, правила `NotificationCenter` десктопа (`core/notify`, решение 440): что сказать — `NotificationPolicy` по смене
состояния туннеля и событиям подписок; показывать ли — `NoticeDesk`:

- окно на экране — в шторку ничего: окно показывает то же само (всплывашки в окне для состояния туннеля нет — оно на
  главной); такое событие считается показанным;
- то же событие — не чаще раза в 10 минут; «Подключено» и «VPN отключен» — только при скрытом окне;
- уровень — «Настройки» → «Уведомления»: «Все», «Только важные» (по умолчанию: обрыв, сервер не отвечает, защита не
  работает), «Выключены» (остается только постоянное уведомление туннеля — его требует Android);
- уведомление о защите одно: новое заменяет прежнее, а беда, которая прошла («Соединение потеряно», когда защита
  вернулась), из шторки убирается; у каждой подписки — свое.

Каналы: «Сбои защиты» (важные, со звуком) и «События» (обычные, тихо). Текст — с сервером, подпиской и причиной (код
ошибки словами и сам код; почему подписка не загрузилась); на экране блокировки — только заголовок. Кнопки: «Сменить
сервер», «Выбрать сервер», «Выбрать другой» — список серверов; «Повторить» и «Подключить» — подключение; «Открыть» у
подписки — «Профили и подписки»; «Позже» — убрать. Работает в процессе приложения и без окна (`ProtectionNotifier`
запускается вместе с приложением): службу запускает и «Постоянная VPN».

## Серверы

- Список (доска 2 в одну колонку): поиск по своему названию, коду страны и протоколу (адрес запечатан, решение 420);
  фильтр протоколов (только тех, что есть в списке) и порядок — по задержке или по названию — панелью под поиском, число
  на кнопке — сколько отличается от обычного; вкладки «Все · N», «Избранные», «Недавние» (10 последних выбранных, свежие
  сверху, решение 421); на «Все» — группы по подпискам в их порядке («обновлено 14:20»), «Мои серверы» последними.
  Пустой список объясняется: серверов нет, избранных нет, ничего не выбирали или ничего не нашлось (решение 422).
  Запрос переживает пересоздание окна (`ServersViewModel`, SavedStateHandle) и в настройки не пишется.
- Строка: страна, название (свое, если переименован), «активен» или «выбран», протокол и порт, «пропал из подписки»,
  задержка — «42 мс» зеленым, больше 120 мс — серым, «нет» — оранжевым (не ответил), «—» — еще не мерили (решение
  428); «⋯» — карточка.
- Нажатие на строку выбирает сервер: тот же — ничего не меняется; другой под защитой (подключение, защищено, ошибка) —
  сразу переподключение без окна утечки (решения 410, 426); без защиты — только выбор. Выбор записывается для «Недавних».
- Задержка — по кнопке «Обновить» («Серверы», быстрая смена на главной) и только без защиты (решение 430): `LatencyMeter`
  берет серверы из запечатанных ссылок, `PingBatch` собирает порции по 5 (тот же выход, что у туннеля, с текущими
  настройками), `CoreEngine.ping` — `pingBatch` libXray с DNS сети и контроллером сокетов, пропускающим каждый (туннеля
  нет). Итоги пишутся порцией; защита включилась во время порции — порция отбрасывается. Запуск ядра туннеля, остановка и
  замер идут по одному, а замер не трогает контроллер работающего туннеля. Hysteria2 и TUIC в libXray не уходят — «нет».
- Быстрая смена на главной — раскрывается в карточке сервера по «Сменить ▾» (решение 431): сервер в работе и два самых
  быстрых измеренных (`QuickSwitch`), «Обновить», «Все серверы ›»; нажатие — как в списке.
- QR: «Добавить» → «Выбрать картинку» — системный выбор фото, ImageDecoder уменьшает до 8 Мп, `QrCode` ищет код (полный
  поиск угловых меток, решение 433); найденное разбирается как введенный текст, в поле не попадает (решение 437).
  «Сканировать камерой» (строка есть, только если у телефона есть камера): доступ к камере спрашивается по нажатию,
  отказ — подсказка в карточке QR; экран сканера — CameraX (задняя камера, нет — передняя; анализ кадров около 1280×720,
  только последний кадр), рамка — центральный квадрат 75 % меньшей стороны, где `QrScanner` ищет код один проход на
  кадр; код прочитан — экран закрывается и текст разбирается так же, как с картинки; камера не открылась — подсказка
  (решение 444).
  «Поделиться» в карточке — QR ссылки (`qrBitmap`: цвет текста макета на белом, поле 4 модуля), предупреждение о ключе,
  «Копировать ссылку» (в буфере — с пометкой «секрет»), «Отправить ссылку», «Скрыть QR»; ссылка открывается только по
  нажатию и пропадает, когда окно уходит в фон (решение 436).
- Карточка (доска 11) — своя страница с «Назад» (решение 427): откуда сервер, избранное, состояние, задержка, сведения
  (адрес открывается из запечатанной ссылки только в открытой карточке, IPv6 — в скобках; протокол, транспорт, защита,
  ядро — Xray-core, у Hysteria2 и TUIC ядра на телефоне нет, решение 423), «Подключиться» (выбор записывается до
  запуска службы — она читает выбранный сервер сама) или «Используется сейчас», свое название (1–64 знака; совпало с
  названием из ссылки — своего нет, решение 429), удаление с подтверждением (защита идет через этот сервер — VPN
  отключается, другой сервер не выбирается сам).

## Подписки

- Обновление — `SubscriptionUpdater` в процессе приложения (решение 434), как `SubscriptionUpdater` десктопа: загрузка
  (`SubscriptionDownloader`, 20 с и 5 МБ) и тот же разбор, что у импорта; новый список — как ApplyUpdate (свое
  пользователя остается, выбранный пропавший — с пометкой); неудача — время, причина и код, прошлый список остается.
- Правило «только через VPN» (по умолчанию включено): пока защита не подключена, адрес подписки в сеть не уходит;
  приложение не исключено из своего VPN — загрузка идет через сервер.
- Когда: переход в «Защищено», каждые 10 минут, пока защита идет (или пока жив процесс, если правило выключено), смена
  настроек и открытие окна — если пора (успех старше промежутка 6/12/24 ч, неудача — не чаще раза в час). Подписка уже
  обновляется — второе нажатие не грузит ее еще раз.
- В фоне, когда процесса приложения нет (решение 443): при автообновлении и выключенном «только через VPN» задача
  WorkManager раз в час при сети спрашивает то же «пора ли» (`SubscriptionWork`); включили правило или выключили
  автообновление — задача снимается. С правилом фоновая задача не нужна: без защиты загрузки нет, а под защитой процесс
  жив — его держит служба VPN.
- Сообщения: выбранный сервер пропал или изменился (если включено «Сообщать об изменении выбранного сервера»), подписка
  по расписанию не обновилась; в журнале — только числа и причина, адресов нет.
- Экран «Профили и подписки» (доска 12 в одну колонку, «Настройки» → раздел): автообновление (выключено, 6, 12, 24 ч),
  «Обновлять только через VPN» с пометкой «защита выключена — подписки не обновляются», «Сообщать об изменении
  выбранного сервера»; карточки — название и состояние («Работает», «Ошибка», «Вручную»), маска адреса, серверы и время
  («обновлено в 18:10», после неудачи — «последняя попытка 5 мин назад»), причина неудачи, «Обновить» (идет — «Загружаем
  подписку…»), «Изменить» (название и новый адрес прямо в карточке; новый адрес сразу проверяется загрузкой; адрес —
  только в Android Keystore), «Удалить» с подтверждением (через сервер группы идет защита — VPN отключается); «Мои
  серверы» — последней карточкой (решение 435).

## Хранение

- Серверы — Room (`private-gateway.db`): открыто — только подписи списка (название, страна, протокол, защита, транспорт,
  порт); сам сервер — ссылка с адресом и ключом — запечатан AES-256-GCM ключом из Android Keystore (`KeystoreSecretBox`,
  ключ `pg-servers-v1` не покидает хранилище устройства). Не открылся (ключ утерян после сброса) — сервер виден в списке,
  удалить можно, подключиться нельзя.
- Дубль — тот же сервер под любым названием: тот же адрес, транспорт, защита и данные доступа (ServerKeys, как у
  десктопа, решение 418).
- Группы: подписка (адрес целиком — запечатан, открыто — маска «https://example.com/sub/••••») или профиль без адреса;
  без названия группы серверы идут в «Мои серверы», адрес не хранится. Обновление подписки — как ApplyUpdate десктопа:
  свои серверы остаются со своим названием, избранным, задержкой и временем выбора, новые добавляются, пропавшие
  удаляются, кроме выбранного (пометка «пропал из подписки»); неудача — время, причина и код ответа, прошлый список
  остается. Записи — по одной и одной транзакцией.
- «Добавить»: одна строка с адресом http(s) — подписка; окно загружает ее (SubscriptionDownloader, 20 с и 5 МБ),
  показывает причину неудачи (import.download.*) и предупреждение для http://; название профиля — из Profile-Title или
  сервер подписки (решение 419). Адрес подписки живет только в памяти окна, в базе — запечатанным.
- Схема — версия 2 (миграция 1 → 2, решение 411): у сервера — группа (подписка или профиль; без группы — «Мои
  серверы»), свое название (в списке — оно, подписка и «Поделиться» берут название из ссылки), избранное, задержка,
  когда выбирался, «пропал из подписки»; подписки — отдельной таблицей: открыто название и маска адреса, адрес целиком —
  запечатан. Схемы с версии 2 — в `app/schemas` (MigrationTestHelper); 1 → 2 проверяет тест на базе по DDL версии 1.
- Настройки — DataStore: выбранный сервер. Первый импорт сам выбирает первый новый сервер, дальше выбор меняет только
  пользователь. Выбранный удален, другие остались — кнопка-щит ведет к списку.
- Добавления в хранилище идут по одному (двойное нажатие не дает дублей); текст импорта живет в модели окна, а не в
  сохраненном состоянии окна (большой конфиг уронил бы процесс, ключи попали бы в системный процесс).
- Резервная копия Android и перенос на другое устройство выключены (`pg_data_extraction.xml`): без ключа Keystore этого
  устройства копия бесполезна, а открытым текстом ее отдавать нельзя.

## Ядро libXray

`scripts/get-libxray.sh` собирает `android/app/libs/libXray.aar` (в git не хранится) из исходников коммита
`android/libxray.version` через gomobile (версия gomobile и gobind — из go.mod libXray, суммы модулей сверяет go.sum),
для всех ABI, с минимальным API 28 и страницами 16 КБ. Нужны go и Android NDK. Версия Xray-core на Android — та, что в
go.mod этого коммита libXray (вход `tun` по дескриптору есть только в новых Xray); на десктопе ядро свое
(`shared/cores/xray.version`).

Один рантайм Go на процесс: других библиотек Go в приложении нет и быть не должно (предупреждение libXray).

- `core` — JUnit 5: разбор на всех эталонах `shared/testdata` и обратно через `LinkWriter`, импорт sing-box и Clash,
  конфиг Xray, план туннеля и DNS ядра, подписки, настройки туннеля, QR-код (те же случаи, что у десктопа, и кадр камеры),

  обратно по правилам Android, экранирование, повтор имен.
- `app` — Robolectric (без устройства, Android 15): хранилище (каждый эталон возвращается тем же, адрес и ключи только
  запечатанными, дубли, одновременные добавления, незапечатанное), настройки, тексты из ресурсов на двух языках и язык
  форм чисел, чипы защиты по состояниям, кнопка-щит, экраны Compose (главная в каждом состоянии, серверы, добавление,
  островок), модель окна.
- Android Lint — его ошибки роняют CI.
- Эмулятор (задание CI «Android (эмулятор)», Android 14 x86_64 с KVM; локально — запущенный эмулятор и
  `scripts/get-xray.sh && scripts/android-test-server.sh`, затем `android/gradlew -p android :app:connectedDebugAndroidTest`):
  настоящий туннель — VpnService, ядро libXray и сервер Xray на машине CI (эмулятор видит ее как 10.0.2.2). Проверочный
  адрес 198.51.100.7 (диапазон документации) напрямую недоступен, а сервер отправляет все соединения на свой HTTP — ответ
  «pg-tunnel-ok» значит, что трафик шел через туннель; после отключения адрес снова недоступен. Согласие на VPN тест
  выдает сам (`appops set … ACTIVATE_VPN allow`): системное окно в проверке не нажать. Без сервера тест пропускается.
