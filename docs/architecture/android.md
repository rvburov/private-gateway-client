# Android

Приложение для Android 9+ (minSdk 28, targetSdk 36): Kotlin, Jetpack Compose, туннель — системный VPN Android
(`VpnService`), ядро — Xray-core внутри процесса приложения (libXray). Экран тот же, что у десктопа: токены, тексты и
правила разбора общие (доски 25–26 макета).

## Где что лежит

```
android/
├── settings.gradle.kts      — модуль app; core и build-logic — составные сборки
├── gradle/libs.versions.toml — версии библиотек и плагинов (как Directory.Packages.props у десктопа)
├── libxray.version          — закрепленный коммит XTLS/libXray (scripts/get-libxray.sh)
├── core/                    — общий модуль на чистом Kotlin, без Android API
├── build-logic/             — плагин сборки: тема и тексты из shared/specifications
└── app/                     — приложение: Compose, VpnService, хранилище
```

| Модуль | Что внутри | Сборка |
| --- | --- | --- |
| `core` | разбор ссылок и подписок (`LinkParser`, `ImportParser`: ссылки, base64, sing-box JSON, Clash YAML), ссылка из сервера (`LinkWriter`), конфиг Xray (`XrayConfig`), план карты туннеля (`TunPlan`), DNS ядра до туннеля и за сменой сети (`CoreDns`, `CoreDnsFollower`), подписи сервера (`ServerFacts`), список серверов — поиск, вкладки, группы, порядок (`ServerList`), быстрая смена (`QuickSwitch`), свое название (`ServerNames`), задержка (`Latency`, замер через libXray — `PingBatch`), подписки (`SubscriptionMerge`, `SubscriptionDownloader`), настройки туннеля (`TunnelSettings`: свой DNS — только IP или DoH по IP, `IpAddress`; DNS в локальной сети идет мимо туннеля — `lanDns`, `PrivateNetwork`; что требует переподключения — `needsReconnect`), QR-код (`QrCode` — картинка, `QrScanner` — кадр камеры, `QrImageSize` — большие фото до 8 Мп, ZXing), `SecretMasker`, формы чисел (`Plural`), API аккаунта сайта (`AccountApi`) и правило доступа (`AccountGate`) | `android/gradlew -p android/core test` — нужен только JDK 17+, без SDK Android и репозитория Google |
| `build-logic` | плагин `privategateway.shared-resources`: задачи `generatePgTheme` и `generatePgResources` | `android/gradlew -p android/build-logic test` — так же без SDK |
| `app` | окно, служба VPN, хранилище, тесты Robolectric | `android/gradlew -p android :app:assembleDebug :app:testDebugUnitTest :app:lintDebug` — нужны SDK Android, NDK для ядра и `scripts/get-libxray.sh` |

Правила те же, что у десктопа, и держатся одинаковыми тестами на общих данных: эталоны `shared/testdata` (разбор), те же
случаи подписей, маскирования и форм чисел, что в тестах .NET.

## Тема, иконки и тексты

Сгенерированных файлов в git нет — плагин `build-logic` собирает их при каждой сборке, и разойтись с источником они не
могут:

- `Tokens.kt` — из `shared/specifications/design-tokens.json`, имена как у `Tokens.axaml` десктопа: `PgColor.Bg.Window`,
  `PgState.Connected.Ring`, `PgType.H1` (TextStyle с размером, начертанием, трекингом и высотой строки в em),
  `PgSpace.Card`, `PgRadius.Card`, `PgShadow.Card`, `PgLayout.Island.Height`. Тест сверяет каждый цвет с `Tokens.axaml`.
- `Icons.kt` — контуры 24×24 из `desktop/src/Client.UI/Themes/Icons.axaml` (`Icon.Nav.Home` → `PgIcons.NavHome`),
  рисуются линией (`PgIcon`).
- `strings.xml` — из `shared/specifications/localization`: `values/` — английский (язык по умолчанию: телефон на любом
  языке, кроме русского), `values-ru/` — русский. Ключ `status.connected.title` → `R.string.status_connected_title`
  («.» и «-» → «_»), подстановка `{0}` → `%1$s`. Два ключа с одним именем ресурса, разные ключи RU и EN — ошибка сборки.
  Тест читает каждый текст обратно через ресурсы Android. Тексты только для телефона — ключи `android.*`.
- иконка запуска (адаптивная, с одноцветным слоем Android 13+) и значок уведомления — щит из `Icons.axaml` цветом
  «Защищено».

Язык приложения — системный или выбранный для приложения в настройках Android 13+ (список языков — `xml/pg_locales.xml`).

  переключатель `PgSwitch` 48 × 28, строка настройки `PgSetting` и `PgSettingSwitch` (`.setting`: заголовок полужирным,
  подпись `text.muted`, полоса `line.divider` между строками), флажок `PgCheck`, сегменты `PgSegments`, строка-ссылка
  `PgLinkRow` (значок в плитке 34, стрелка «›» справа). Прежние `PgToggleRow` и `PgChoiceRow` — тем же видом: строка
  настройки с переключателем и пункт `.btn-option` (выбранный — синим полужирным, без кружка).
- `Menus.kt` — кнопка-список `PgSelectButton` и меню у нее `PgMenu` (Popup: на 8 под кнопкой по ее правому краю, вниз не
  помещается — над ней; закрывается нажатием вне меню и «Назад»), пункты `PgMenuOption` и `PgMenuAction`; `PgSelect` — все
  вместе.
- `Layers.kt` — диалог подтверждения `PgDialog` (`.dialog`: значок в плитке тона `PgTone`, заголовок, текст, основная и
  второстепенная кнопки), нижний лист `PgSheet` (`.sheet` с ручкой) и подсказка сверху `PgToast` (`.toast`). Лист и диалог —
  в своем окне от края до края, затемнение `overlay.scrim` у них свое (системное снято), нажатие на затемнение и «Назад»
  закрывают слой. Подсказку показывает окно (`AppScreen`); экран зовет ее через `LocalPgToast`: 1,8 с после действия,
  6 с о событии (`Message.long` — сообщения подписок о выбранном сервере). Системный `Toast` приложение больше не
  показывает.
- Вопрос перед выбором — `PgConfirm`: сегменты, меню и строка с переключателем сами не переключаются, а отдают новое
  значение и функцию `apply`; экран показывает диалог и зовет `apply` на «Да» (как `ConfirmRadioButton` и `ConfirmSwitch`
  десктопа, решение 529).
- `Theme.kt` — фон окна `PgBackground`: три пятна `color.decor` на местах `.pg-app` макета (градиент сплошной до 35 % и
  прозрачный к 70 %) и над ними слой стекла `glass.fill`; карточка `PgCard` — и со своими полями (`contentPadding`) для строк
  до краев карточки. Для Android фон заранее смешивается: `surface.card.compositeOver(bg.window)`. Готовая заливка
  непрозрачна, поэтому системная тень не просвечивает внутрь. Обычные строки прозрачны; цветные чипы, значки и кнопки
  сохраняют собственные заливки. Общие токены остаются прежними. Причина выбора заливки и
  границы проверки — [разбор белых прямоугольников Android](../operations/incidents/2026-11-05-android-card-background.md).
- Островок — `ui/Island.kt`: контур `IslandGeometry` десктопа (плашка и выступ вокруг щита одним контуром, заливка
  `surface.solid`, обводка `line.divider`, тень `shadow.island`), колонка под щитом 76, пункт — значок 24 линией 1.7 и
  подпись по центру полосы, активный залит `accent.navActiveFill`; щит при нажатии заливается `state.*.fill` и сжимается до
  0,96, дуга ожидания — 0,9 с. Пункт островка всегда ведет на свой экран: «Серверы» закрывает открытую карточку сервера.

## Туннель

`GatewayVpnService` (`VpnService`, служба переднего плана типа specialUse с подтипом vpn):

1. Окно спрашивает разрешение Android на VPN (`VpnService.prepare` — системное окно один раз) и на уведомления (Android
   13+), затем запускает службу. «Постоянная VPN» запускает ее сама (действие `android.net.VpnService`,
   `SUPPORTS_ALWAYS_ON`).
2. Служба берет выбранный сервер (другой сам не выбирается), настройки туннеля (DNS, IPv6 через сервер, локальная сеть —
   DataStore) и DNS текущей сети — до того как сетью станет туннель.
3. Карта туннеля по `TunPlan`: адрес `172.19.0.1/30`, маршрут `0.0.0.0/0` — весь IPv4, DNS `172.19.0.2` — внутри
   туннеля, его запросы ядро отвечает через сервер (правило «порт 53 → выход DNS» в конфиге). IPv6: без настройки «IPv6
   через сервер» у туннеля нет адреса и маршрута IPv6 — тогда Android сам закрывает IPv6 всем программам, и они сразу
   уходят на IPv4. Сеть под туннелем считается платной, только если платная она сама (`setMetered(false)`).
4. Ядро — libXray: конфиг Xray с входом `tun` по дескриптору карты (`env.xray.tun.fd`); сокеты ядра выводятся из
   туннеля (`protect` через `registerDialerController`), адрес сервера ядро находит через DNS сети (`setDNS`, защищенный
   сокет). Xray читает свою копию дескриптора; карту закрывает приложение — после остановки ядра. Контроллер сокетов —
   один на процесс (Xray хранит каждый до конца процесса и снять не дает), за ним меняется только работающая служба.
5. Сеть телефона меняется (Wi-Fi ↔ мобильная, новый DNS): служба следит за лучшей сетью с интернетом, кроме VPN (Android
   12+ `registerBestMatchingNetworkCallback`, раньше `requestNetwork`), и передает ядру DNS новой сети (`CoreDnsFollower`):
   DNS прежней сети из новой обычно недоступен, и сервер по имени перестал бы находиться. Сеть под туннелем Android берет
   сам — сеть по умолчанию.
6. Состояние — `TunnelMonitor` (общий поток службы и окна; типы — `core/vpn/TunnelStatus.kt`): Выключено, Подключение,
   Защищено, Переподключение (с номером попытки), Отключение, Ошибка с кодом.
   Под защитой служба передает и то, что Android сообщает только работающему VPN (Android 10+): включены ли «Постоянная
   VPN» и «Блокировать подключения без VPN».
7. Уведомление туннеля (доска 26, канал «Защита», без звука) — «IP скрыт · сервер», шифруется ли трафик, «в сети» с
   таймером, «Отключить» и «Сменить сервер» (открывает «Серверы»); во время переподключения — «Переподключение…» и сервер.
   На экране блокировки — только состояние, без названия сервера (`docs/security/review.md`).
   Остальные уведомления — раздел «Уведомления» ниже. Отзыв VPN (другая программа включила свой VPN, пользователь отключил
   в настройках) — отключение.
8. Остановка гасит службу по номеру своего запуска (`stopSelfResult`): подключение, пришедшее после «Отключить», службу
   не теряет. Служба уничтожена посреди подключения — подключение само снимает туннель и ядро.
9. Плитка в шторке (`GatewayTileService`, доска 26) включает и выключает VPN без окна: к выбранному серверу и только
   после разблокировки экрана; сервера нет или нет разрешения на VPN — открывает окно (решение 415).
10. Переподключение (другой сервер, новые настройки) — без окна утечки: новая карта поднимается, пока прежняя держит
   трафик (Android заменяет одну другой), и только потом останавливается прежнее ядро; до запуска нового пакеты ждут в
   карте, а не уходят мимо туннеля.
11. Проверка профиля до «Защищено» (`StartCheck`, решение 556): ядро запустилось — это еще не связь. До двух проб через
   туннель с таймаутом подключения и паузой в секунду между ними, к `https://1.1.1.1/` по IP — свой DNS пользователя может
   быть недоступен, а проверяется путь через сервер; ни одна не ответила — «Ошибка» с кодом `PGC-NET-001` и уведомление «Сервер не отвечает»
   с «Повторить» и «Выбрать сервер» (при «Блокировать подключения без VPN» — что интернет заблокирован), а не «Защищено» и
   бесконечное «Переподключение». Так неверный ключ, неработающий сервер подписки или блокировка провайдером видны сразу.
12. Пауза для входа в Wi-Fi (`CaptivePause`, решение 557): `ACTION_PAUSE` опускает туннель и ядро на 5 минут, состояние —
   «Выключено» с `pausedUntil`; служба остается на переднем плане с уведомлением «Защита на паузе» (обратный отсчет,
   «Вернуть защиту», «Отключить») и через 5 минут подключается сама. При «Блокировать подключения без VPN» окно паузу не
   предлагает: Android держит сеть закрытой и без туннеля.
13. Связь с сервером (`core/vpn/TunnelGuard.kt` — `WatchLoopAsync` и `ReconnectLoopAsync` десктопа, решение 441): пока
   защита включена, служба пробует связь — запрос HEAD к `cp.cloudflare.com/generate_204` из процесса приложения, то есть
   через туннель (приложение из своего VPN не исключено), срок 10 с; сразу после подключения и дальше раз в минуту. Одна
   неудача бывает и у живого сервера — вторая проба сразу; две подряд — обрыв: «Переподключение» к тому же серверу (другой
   сам не выбирается). Попытка — тот же запуск карты и ядра (путь без окна утечки) и проба; паузы 1, 2, 4… до 60 с.
   Политика — «Настройки» → «Переподключение»: «Экспоненц. до 60 с» (пока пользователь не выключит), «До 5 минут»,
   «Не повторять»; кончилась — «Ошибка» с кодом `PGC-NET-001` или кодом последней неудачи; сервер удален, VPN занят
   другой программой, ядро не берется за сервер — «Ошибка» сразу. Сеть сменилась (Wi-Fi ↔ мобильная) или телефон вышел из
   глубокого сна (Doze) — проба или попытка сразу. Все это время карта туннеля держит трафик: он ждет, а не идет мимо.

Коды ошибок — те же, что у десктопа (`docs/architecture/errors.md`): `PGC-NET-001` — сервер не отвечает (переподключение
сдалось), `PGC-SVC-002` — ядро не запустилось,
`PGC-SVC-003` — сервер не выбран или удален, `PGC-SVC-005` — ядро не умеет этот сервер (Hysteria2 и TUIC: на Android
второго ядра нет), `PGC-NET-010` — Android не дал поднять VPN (место занял VPN другой программы или разрешение отозвано).
Текст ошибки ядра пишется в журнал Android только через `SecretMasker`.

«Работает другой VPN» (DECISIONS.md, п. 4). Android отозвал VPN (`onRevoke`) — туннель и ядро снимаются сразу, затем
`OtherVpn.tookOver` до 3 с ждет VPN другого приложения (`PhoneHints.otherVpn`: сеть VPN не наша — с Android 11 Android
называет владельца; первая проверка через 0,5 с, чтобы свой опущенный туннель не сошел за чужой). Появился — «Ошибка»
PGC-NET-010, важное уведомление «Работает другой VPN» (`NoticeKind.OtherVpn`) и страница проблемы вместо главной
(`OtherVpnScreen`, доска 16): «Я закрыл его — проверить снова» (VPN все еще занят — подсказка, свободен — подключение),
«Открыть настройки VPN», ссылка на журнал. Не появился — пользователь выключил VPN в настройках Android: «Выключено».
Android не дал разрешения на VPN, а VPN телефона занят другим приложением (его «Постоянная VPN» не пускает наш) — та же
страница вместо подсказки «Android не дал разрешения».

Настройки туннеля — «Настройки» → «Защита и утечки» (решения 412–414): DNS в туннеле (из профиля, DoH Cloudflare, DoH
Quad9, свой адрес — только IP или DoH по IP), «Приоритет адресов» («Только IPv4» — IPv6 закрыт Android, «Предпочитать
IPv4» — IPv6 через сервер), «Разрешить локальную сеть». Под защитой изменение само переподключает туннель через 0,7 с
тишины — путем без окна утечки; то, что ядра не меняет, переподключения не требует.

Подписки с «только через VPN» используют сеть нашей карты (`OwnVpnNetwork`) с закрепленным сокетом
(`Network.socketFactory`) и отдельный аутентифицированный HTTP-вход Xray.
Первое правило этого входа отправляет HTTP и HTTPS CONNECT в выбранный сервер раньше правил LAN/DNS; имя подписки
разрешает сервер. Клиент OkHttp имеет свой аутентификатор прокси, прямой DNS для него запрещен, пароль не уходит на сайт.
Android 11+ подтверждает UID владельца сети; на Android
9–10 принимается только новая сеть после нашего `establish` с адресами карты, либо ранее подтвержденная своя при передаче
карты. Чужая или прежняя неизвестная VPN, отсутствие разрешения и неподтвержденная карта — отказ, без запасного пути
через сеть по умолчанию. Остановка, отзыв VPN и отмена запроса закрывают активный запрос; каждый переход остается в том же входе.
Исключение — WireGuard, который разрешает имя сам: отдельный маршрут локального DNS или разрешенная LAN с DNS/DoH
на адресе из `XrayConfig.localNetworks` не дают гарантии «только через сервер». Учитываются и loopback, CGN, ULA,
особые диапазоны и IPv4 внутри IPv6. При разрешенной LAN неизвестное имя DNS тоже отклоняется без DNS-запроса.
В этих сочетаниях обновление отказывает с понятной причиной; публичный числовой DNS/DoH (например DoH Cloudflare)
сохраняет этот режим. Остальные протоколы передают имя подписки выбранному серверу и не имеют этого ограничения.

Блок при обрыве на Android — системный: «Постоянная VPN» и «Блокировать подключения без VPN» включает только пользователь
в настройках VPN телефона; «Настройки» открывают их кнопкой, чип «Блок при обрыве» показывает то, что сообщил Android.

«Постоянная VPN» и блок без VPN (решение 445):

- Android сообщает флаги только работающему туннелю (Android 10+); служба запоминает их при каждом подключении
  (DataStore). Карточка «VPN в настройках Android» показывает оба флага («вкл», «выкл», «неизвестно») и откуда они: «Так
  сейчас сообщает Android» под защитой, «при последнем подключении» без нее, «появятся после подключения» — если Android
  их еще не сообщал (`SystemVpnView`).
- Закрыта ли сеть приложению самим Android, приложение узнает сразу, без подключения: сеть по умолчанию и ее блокировка
  (`NetworkAccess`, `onBlockedStatusChanged`, Android 10+). Без туннеля при «Блокировать подключения без VPN» главная
  говорит «Интернет закрыт Android: без VPN подключения блокируются», чипы — как у сработавшего блока десктопа (трафик
  остановлен, DNS и IPv6 — утечки нет, блок — сработал), «Ошибка» — «трафик заблокирован», а не «идет напрямую».
- Замер задержки при закрытой сети не идет («Задержка не меряется: Android закрыл интернет без VPN»): иначе все серверы
  «не ответили» бы из-за блока; закрылась во время порции — порция отбрасывается.
- «Постоянная VPN» запускает службу сама; подключение — к выбранному серверу, без него — «Ошибка» с кодом и уведомление.

## Уведомления

Доска 22, правила `NotificationCenter` десктопа (`core/notify`, решение 440): что сказать — `NotificationPolicy` по смене
состояния туннеля и событиям подписок; показывать ли — `NoticeDesk`:

- окно на экране — в шторку ничего: окно показывает то же само (всплывашки в окне для состояния туннеля нет — оно на
  главной); такое событие считается показанным;
- то же событие — не чаще раза в 10 минут; «Подключено» и «VPN отключен» — только при скрытом окне;
- уровень — «Настройки» → «Уведомления»: «Все», «Только важные» (по умолчанию: обрыв, сервер не отвечает, защита не
  работает), «Выключены» (остается только постоянное уведомление туннеля — его требует Android);
- уведомление о защите одно: новое заменяет прежнее, а беда, которая прошла («Соединение потеряно», когда защита
  вернулась), из шторки убирается; у каждой подписки — свое.

Каналы: «Сбои защиты» (важные, со звуком) и «События» (обычные, тихо). Текст — с сервером, подпиской и причиной (код
ошибки словами и сам код; почему подписка не загрузилась); на экране блокировки — только заголовок. Кнопки: «Сменить
сервер», «Выбрать сервер», «Выбрать другой» — список серверов; «Повторить» и «Подключить» — подключение; «Открыть» у
подписки — «Профили и подписки»; «Позже» — убрать. Работает в процессе приложения и без окна (`ProtectionNotifier`
запускается вместе с приложением): службу запускает и «Постоянная VPN».

## Серверы

- Список (доска 2 в одну колонку): поиск по своему названию, коду страны и протоколу (адрес запечатан, решение 420);
  фильтр протоколов (только тех, что есть в списке, флажками в две колонки) и порядок — по задержке или по названию,
  сегментами — панелью поверх вкладок и списка, на 6 под полем поиска (закрывается нажатием мимо, «Готово» и «Назад»,
  решение 540), число на кнопке — сколько отличается от обычного; шапка, поиск и вкладки стоят, прокручивается список; вкладки «Все · N», «Избранные», «Недавние» (10 последних выбранных, свежие
  сверху, решение 421); на «Все» — группы по подпискам в их порядке («обновлено 14:20»), «Мои серверы» последними.
  Пустой список объясняется: серверов нет, избранных нет, ничего не выбирали или ничего не нашлось (решение 422).
  Запрос переживает пересоздание окна (`ServersViewModel`, SavedStateHandle) и в настройки не пишется.
- Строка (как доска 2): значок страны 40×28, название (свое, если переименован), метка «активен» (только в «Подключено» и
  у сервера туннеля) или «выбран» зеленой плашкой справа, протокол моноширинным (порт — в карточке, адрес запечатан),
  задержка — «42 мс» зеленым, больше 120 мс — серым, «нет» — оранжевым (не ответил), «—» — еще не мерили (решение
  428); «⋯» — карточка.
- Нажатие на строку выбирает сервер: тот же — ничего не меняется; другой под защитой (подключение, защищено, ошибка) —
  сразу переподключение без окна утечки (решения 410, 426); без защиты — только выбор. Выбор записывается для «Недавних».
- Задержка — по кнопке «Обновить» («Серверы», быстрая смена на главной) и только без защиты (решение 430): `LatencyMeter`
  берет серверы из запечатанных ссылок, `PingBatch` собирает порции по 5 (тот же выход, что у туннеля, с текущими
  настройками), `CoreEngine.ping` — `pingBatch` libXray с DNS сети и контроллером сокетов, пропускающим каждый (туннеля
  нет). Итоги пишутся порцией; защита включилась во время порции — порция отбрасывается. Запуск ядра туннеля, остановка и
  замер идут по одному, а замер не трогает контроллер работающего туннеля. Hysteria2 и TUIC в libXray не уходят — «нет».
- Быстрая смена на главной — раскрывается в карточке сервера по «Сменить ▾» (решение 431): сервер в работе и два самых
  быстрых измеренных (`QuickSwitch`), «Обновить», «Все серверы ›»; нажатие — как в списке.
- QR: «Добавить» → «Выбрать картинку» — системный выбор фото, ImageDecoder уменьшает до 8 Мп, `QrCode` ищет код (полный
  поиск угловых меток, решение 433); найденное разбирается как введенный текст, в поле не попадает (решение 437).
  «Сканировать камерой» (строка есть, только если у телефона есть камера): доступ к камере спрашивается по нажатию,
  отказ — подсказка в карточке QR; экран сканера — CameraX (задняя камера, нет — передняя; анализ кадров около 1280×720,
  только последний кадр), рамка — центральный квадрат 75 % меньшей стороны, где `QrScanner` ищет код один проход на
  кадр; код прочитан — экран закрывается и текст разбирается так же, как с картинки; камера не открылась — подсказка
  (решение 444).
  «Поделиться» в карточке — QR ссылки (`qrBitmap`: цвет текста макета на белом, поле 4 модуля), предупреждение о ключе,
  «Копировать ссылку» (в буфере — с пометкой «секрет»), «Скрыть QR» — на месте сведений карточки; «Отправить ссылку» убрана
  (ключ не уходит через Intent в чужие программы, решение 540); ссылка открывается только по нажатию и пропадает, когда
  окно уходит в фон (решение 436); ключа нет — подсказка поверх листа и недоступная плитка.
- Карточка (доска 11) — нижний лист поверх списка (`PgSheet`, решение 540; было — страница, решение 427): ручка, крестик,
  закрытие нажатием мимо и «Назад», заголовок и плитки «Переименовать · Поделиться · Удалить» стоят, середина прокручивается; откуда сервер, избранное, состояние, задержка, сведения
  (адрес открывается из запечатанной ссылки только в открытой карточке, IPv6 — в скобках; «Выходной IP» — последний IP,
  который сайты видели через сервер, или «Не измерен»: запоминается после «Подключено» с замером этого подключения, без
  утечки и паузы, и хранится запечатанным, решения 583 и 607; протокол, транспорт, защита,
  ядро — Xray-core, у Hysteria2 и TUIC ядра на телефоне нет, решение 423), «Подключиться» (выбор записывается до
  запуска службы — она читает выбранный сервер сама) или «Используется сейчас», свое название (1–64 знака; совпало с
  названием из ссылки — своего нет, решение 429; переименование — на месте сведений), «Подключиться» у Hysteria2 и TUIC
  недоступна (ядра на телефоне нет), удаление с подтверждением (`PgDialog`, после — «Сервер удален») (защита идет через этот сервер — VPN
  отключается, другой сервер не выбирается сам).

## Подписки

- Обновление — `SubscriptionUpdater` в процессе приложения (решение 434), как `SubscriptionUpdater` десктопа: загрузка
  (`SubscriptionDownloader`, 20 с и 5 МБ) и тот же разбор, что у импорта; новый список — как ApplyUpdate (свое
  пользователя остается, выбранный пропавший — с пометкой); неудача — время, причина и код, прошлый список остается.
- Правило «только через VPN» (по умолчанию включено): пока защита не подключена, адрес подписки в сеть не уходит;
  приложение не исключено из своего VPN — загрузка идет через сервер.
- Когда: переход в «Защищено», каждые 10 минут, пока защита идет (или пока жив процесс, если правило выключено), смена
  настроек и открытие окна — если пора (успех старше промежутка 6/12/24 ч, неудача — не чаще раза в час). Подписка уже
  обновляется — второе нажатие не грузит ее еще раз.
- В фоне, когда процесса приложения нет (решение 443): при автообновлении и выключенном «только через VPN» задача
  WorkManager раз в час при сети спрашивает то же «пора ли» (`SubscriptionWork`); включили правило или выключили
  автообновление — задача снимается. С правилом фоновая задача не нужна: без защиты загрузки нет, а под защитой процесс
  жив — его держит служба VPN.
- Сообщения: выбранный сервер пропал или изменился (если включено «Сообщать об изменении выбранного сервера»), подписка
  по расписанию не обновилась; в журнале — только числа и причина, адресов нет.
- Экран «Профили и подписки» (доска 12 в одну колонку, «Настройки» → раздел): автообновление (выключено, 6, 12, 24 ч),
  «Обновлять только через VPN» с пометкой «защита выключена — подписки не обновляются», «Сообщать об изменении
  выбранного сервера»; карточки — название и состояние («Работает», «Ошибка», «Вручную»), маска адреса, серверы и время
  («обновлено в 18:10», после неудачи — «последняя попытка 5 мин назад»), причина неудачи, «Обновить» (идет — «Загружаем
  подписку…»), «Изменить» (название и новый адрес прямо в карточке; новый адрес сразу проверяется загрузкой; адрес —
  только в Android Keystore), «Удалить» с подтверждением (через сервер группы идет защита — VPN отключается); «Мои
  серверы» — последней карточкой (решение 435).

## Инспектор сети

«Проверка» под пунктами защиты — инспектор сети в пределах того, что Android дает приложению (решение 448). Тексты и
правила — десктопа (стр. 7): подписи `network.*` и `probe.*`, разбор узла, сведения RIPEstat.

- Сети телефона (`PhoneNetworkReader`): все сети, которые Android сообщает приложению, и VPN — свой или чужой: вид,
  интерфейс, сеть по умолчанию приложения, адреса IPv4 и IPv6 с префиксами, шлюзы, DNS, «Частный DNS» (выключен,
  автоматически или имя сервера), MTU (Android 10+), лимитная ли, проверил ли Android выход в интернет, нужен ли вход в
  Wi-Fi. Обновляется по сообщениям Android, без опроса; только чтение.
- Внешний IP — по кнопке «Измерить», запросом из процесса приложения к `1.1.1.1/cdn-cgi/trace` (тот же источник, что у
  десктопа): под защитой — адрес выхода сервера («Через сервер»), без нее — провайдера («Напрямую»). «Кто провайдер» —
  RIPEstat (`prefix-overview`, `maxmind-geo-lite`), о частном и служебном адресе — без запроса (`PublicAddress`).
- Замеры DNS, TCP и TLS (`ProbeRunner` в общем модуле) из процесса приложения: под защитой — через туннель. TLS —
  рукопожатие с SNI и ALPN (Android 10+), сертификат проверяется по пунктам: срок по часам телефона, имя по SAN (у адреса —
  только IP из SAN), цепочка — доверенными корнями телефона; отзыв не проверяется.
- Чего нет на Android: пинга и пути (сырых сокетов и ICMP у приложений нет), списка соединений и процессов (Android 10+
  закрыл их приложениям), аренды DHCP и MAC. Так и сказано на экране; узел проверяют замеры DNS, TCP и TLS.
- В журнал инспектор ничего не пишет: адреса и узлы — только на экране.

## Аккаунт сайта

Пользоваться защитой можно только с действующим входом в аккаунт сайта Private Gateway Web (решения 616–623, общие с
десктопом). Решение о доступе принимает сайт, в приложении секретов нет.

- **API** — `core/account/AccountApi`: `POST /api/app/login`, `GET /api/app/status`, `POST /api/app/logout` на постоянный
  адрес `https://private-gateway.duckdns.org` (http — только 127.0.0.1 в тестах), `HttpURLConnection` без перехода по
  перенаправлениям, 15 с, ответ не больше 64 КБ. Итог — причина (`AccountError`: 401, 400, 403, 409, 429 с минутами из
  Retry-After вверх, 422, сеть, ошибка сайта) или вид ответа проверки (`StatusResult.Ok`, `Revoked` — только 401,
  `Unreachable` — сеть, 5xx, мусор). Тела ошибок и тексты исключений наружу не идут; токен, пароль, коды и почта — только в
  теле запроса и заголовке Authorization.
- **Правило доступа** — `core/account/AccountGate`: отзыв — только 401; без ответа сайта действует последний
  подтвержденный срок (`expires_at`); срок прошел — выход «Срок входа истек». Проверка — при запуске процесса
  (`PrivateGatewayApp`), при открытии окна (`MainViewModel.windowShown`, не чаще раза в минуту) и раз в 30 минут, пока
  жив процесс.
- **Хранение** — `account/AccountRepository`: свой DataStore `account` (`@AccountStore`), мимо настроек и их резервной
  копии. Токен — только запечатанным `SecretBox` (ключ Android Keystore), Base64; Keystore не работает — вход не
  выполняется (`account.error.store`), токен без защиты не хранится. Рядом открыто: срок, почта, имя, имя устройства на
  сайте, время последней проверки. uid устройства — случайный GUID, создается один раз на установку, выход его не стирает;
  бэкап и перенос Android выключены, так что на другой телефон он не переезжает. Имя для сайта —
  `DeviceInfo.phoneName(Build.MANUFACTURER, Build.MODEL)`, версия — `BuildConfig.VERSION_NAME`.
- **Ворота** — `ui/AppScreen`: пока вход не прочитан — пустой фон; входа нет — `ui/account/LoginScreen` до любого
  другого экрана, и до приветствия первого запуска, без островка; язык RU/EN — на экране входа. Форма — почта, пароль с
  «глазом», код 2FA (только цифры, 6) или резервный код, «Войти» («Вход…» во время запроса), Enter в поле кода
  отправляет; после ответа пароль и код стираются, почта остается. У 403 и 409 под ошибкой — кнопка на страницу сайта
  (`/login`, `/devices`). Отзыв или истечение — плашка `account.revoked` / `account.expired` над формой.
- **Запрет подключения** — `GatewayVpnService.connect`: без действующего входа ядро не запускается, состояние «Ошибка» с
  кодом `PGC-ACC-001`. Сюда приходят все пути: кнопка, уведомление, «Постоянная VPN», перезапуск системой. Плитка без
  входа открывает окно, «Подключаться при запуске» без входа не срабатывает. Отзыв или истечение во время работы — защита
  выключается (`TunnelControl.disconnect`), служба выключенной защиты не будится.
- **Выход** — «Настройки» → карточка «Аккаунт» (имя, почта, «Это устройство: …») → «Выйти» с подтверждением: защита
  выключается, вход стирается (uid остается), сайт получает `logout` (ошибка сети не мешает), экран входа — с пустыми
  полями.
- Под системной «Блокировать подключения без VPN» без туннеля интернета нет и у самого приложения: после отзыва или
  выхода войти снова можно, только выключив этот блок в настройках Android. Без ответа сайта (в том числе из-за блока)
  доступ не отзывается до конца подтвержденного срока.
- Проверки на устройстве (androidTest) засевают вход `AccountRepository.seedForTests` (`TestAccount`): демо-режима у
  телефона нет, настоящий сайт поддельный токен не примет. Засеянный вход сайт не проверяет. Отказ службы без входа
  проверяет `TunnelOnDeviceTest` (`signOutForTests` стирает вход без запроса к сайту).

## Хранение

- Серверы — Room (`private-gateway.db`): открыто — только подписи списка (название, страна, протокол, защита, транспорт,
  порт); сам сервер — ссылка с адресом и ключом — запечатан AES-256-GCM ключом из Android Keystore (`KeystoreSecretBox`,
  ключ `pg-servers-v1` не покидает хранилище устройства). Не открылся (ключ утерян после сброса) — сервер виден в списке,
  удалить можно, подключиться нельзя.
- Повторно добавленная ссылка подписки (тот же адрес целиком, с токеном, — `SubscriptionAddress.same`) обновляет ту же
  группу (`applyUpdate`), экран «Добавить» заранее говорит об этом; ссылки с названием существующего профиля без адреса —
  в этот профиль; группы с одним адресом, созданные раньше, объединяются один раз при запуске (`mergeSameSubscriptions`,
  решение 528). Адрес подписки для подписи — звездочками, старые точки заменяются при показе (решение 531).
- Дубль — тот же сервер под любым названием: тот же адрес, транспорт, защита и данные доступа (ServerKeys, как у
  десктопа, решение 418).
- Группы: подписка (адрес целиком — запечатан, открыто — маска «https://example.com/sub/••••») или профиль без адреса;
  без названия группы серверы идут в «Мои серверы», адрес не хранится. Обновление подписки — как ApplyUpdate десктопа:
  свои серверы остаются со своим названием, избранным, задержкой и временем выбора, новые добавляются, пропавшие
  удаляются, кроме выбранного (пометка «пропал из подписки»); неудача — время, причина и код ответа, прошлый список
  остается. Записи — по одной и одной транзакцией.
- HTTP-подписки намеренно разрешены политикой Android (`usesCleartextTraffic`); перед добавлением показывается
  предупреждение об открытой передаче ключей. Для HTTPS остаются обычная проверка сертификата и запрет перехода на HTTP.
- «Добавить»: одна строка с адресом http(s) — подписка; окно загружает ее (SubscriptionDownloader, 20 с и 5 МБ),
  показывает причину неудачи (import.download.*) и предупреждение для http://; название профиля — из Profile-Title или
  сервер подписки (решение 419). Адрес подписки живет только в памяти окна, в базе — запечатанным.
- Схема — версия 3 (миграции 1 → 2, решение 411, и 2 → 3, решение 607): у сервера — группа (подписка или профиль; без
  группы — «Мои серверы»), свое название (в списке — оно, подписка и «Поделиться» берут название из ссылки), избранное,
  задержка, когда выбирался, «пропал из подписки», запечатанный выход (`sealedExit`); подписки — отдельной таблицей:
  открыто название и маска адреса, адрес целиком — запечатан. Схемы с версии 2 — в `app/schemas` (CI сверяет их с
  сущностями); миграции проверяет `MigrationTest` на базах по DDL версий 1 и 2.
- Настройки — DataStore: выбранный сервер. Первый импорт сам выбирает первый новый сервер, дальше выбор меняет только
  пользователь. Выбранный удален, другие остались — кнопка-щит ведет к списку.
- Добавления в хранилище идут по одному (двойное нажатие не дает дублей); текст импорта живет в модели окна, а не в
  сохраненном состоянии окна (большой конфиг уронил бы процесс, ключи попали бы в системный процесс).
- Резервная копия Android и перенос на другое устройство выключены (`pg_data_extraction.xml`): без ключа Keystore этого
  устройства копия бесполезна, а открытым текстом ее отдавать нельзя.

## Ядро libXray

`scripts/get-libxray.sh` собирает `android/app/libs/libXray.aar` (в git не хранится) из исходников коммита
`android/libxray.version` через gomobile (версия gomobile и gobind — из go.mod libXray, суммы модулей сверяет go.sum),
для всех ABI, с минимальным API 28 и страницами 16 КБ. Нужны go и Android NDK. Версия Xray-core на Android — та, что в
go.mod этого коммита libXray (вход `tun` по дескриптору есть только в новых Xray); на десктопе ядро свое
(`shared/cores/xray.version`).

Один рантайм Go на процесс: других библиотек Go в приложении нет и быть не должно (предупреждение libXray).

## Лицензии открытых компонентов

Список — `shared/licenses/android.json`, в формате `components.json` десктопа (решение 449): компонент приходит модулями
Maven (`maven`, шаблоны «группа:имя», «*» в конце — любой хвост), своим .aar (`aar`, версия — `android/<имя>.version`)
или внутри другого компонента (`inside`: Xray-core — внутри libXray). Задача `generatePgLicenses` (build-logic) при
каждой сборке сверяет список с runtime-зависимостями выпуска (`releaseRuntimeClasspath`, граф Gradle) и пишет в assets:

- `licenses/components.json` — для экрана: модуль идет к компоненту с самым длинным подходящим шаблоном
  (`androidx.compose.ui:ui` — Jetpack Compose, а не AndroidX), версии — из графа;
- `licenses/<SPDX>.txt` — полные тексты нужных лицензий из `shared/licenses/texts` (общие с десктопом);
- `THIRD-PARTY-NOTICES.txt` — все то же одним файлом, как у выпуска десктопа;
- `sbom.cdx.json` — SBOM приложения (CycloneDX 1.6, решение 453), как `<имя>.cdx.json` выпуска десктопа: каждый модуль
  выпуска — `pkg:maven/группа/имя@версия` с лицензией своего компонента, libXray — `pkg:github/XTLS/libXray@<коммит>`,
  Xray-core — вложенным компонентом libXray. Без времени и серийного номера: сборки одного коммита дают один файл.
  CI кладет его рядом с APK в артефакт (`app-debug.cdx.json`, взят из самого APK).

Модуль без строки, строка без модулей, .aar без версии или лицензия без текста — ошибка сборки со всем списком: новая
библиотека не попадет в APK без строки о ней. Экран — «Настройки» → «О программе» → «Лицензии открытых компонентов»:
имя и лицензия, по нажатию — авторство, ссылки (открываются в браузере), версия, модули и полный текст лицензии.

Обновления (DECISIONS.md, п. 8) — только кнопка «Проверить» в «О программе», фоновой проверки и уведомления нет:
`UpdateCheck` (core) по тем же правилам, что служба десктопа (`docs/architecture/release.md`, «Проверка обновлений»),
берет выпуски с API GitHub, у новее установленного — `update.json` и `update.json.sig` только из загрузок выпусков этого
репозитория, сверяет подпись ECDSA P-256 открытыми ключами `shared/update/keys/*.pem` (сборка кладет их в
`assets/update-keys`, задача `generatePgUpdateKeys`), версию манифеста с тегом, канал и долю раскатки (0 — выпуска нет).
Канал — по установленной версии: бета видит беты. Итог — «Установлена последняя версия · проверено в 15:42», «Доступна
версия 0.2.0» с «Открыть выпуск» (APK ставят со страницы выпуска), «с первого подписанного выпуска», пока ключей нет, или
«не удалось» с записью в журнал «Проверки». Загрузка (`AppUpdates`) — из процесса приложения, только HTTPS, до 256 КБ.

  ядру не передается — сертификат проверяется всегда (в Xray-core 26.x флаг удален, решение 477); самоподписанный сертификат
  закрепляется в ссылке — «pcs» и «vcn» идут в `pinnedPeerCertSha256` и `verifyPeerCertByName` (решение 480).
- `build-logic` — JUnit 5 на настоящих файлах репозитория: цвета совпадают с `Tokens.axaml`, все тексты RU и EN читаются

  модуль идет к самому точному компоненту, непокрытый модуль, устаревшая строка, нет текста или версии .aar — ошибка.
- `app` — Robolectric (без устройства, Android 15): хранилище (каждый эталон возвращается тем же, адрес и ключи только
  запечатанными, дубли, одновременные добавления, незапечатанное), настройки, тексты из ресурсов на двух языках и язык
  форм чисел, чипы защиты по состояниям, кнопка-щит, экраны Compose (главная в каждом состоянии, серверы, добавление,
  островок), блоки дизайн-системы (`ControlsTest`: сегменты и вопрос перед выбором, меню, флажок, строка с переключателем,

  `LoginScreenTest`: форма, ошибки и кнопки сайта, ширина 360, карточка «Аккаунт» с подтверждением выхода); лицензии — то, что сборка положила в assets, и экран «Лицензии открытых компонентов».
  В ожиданиях `MainViewModelTest` и `SubscriptionsViewModelTest` при исходном пределе 10 с печатаются дампы корутин и
  потоков, затем повторно бросается та же ошибка: это отличает ожидание Room от DataStore при редком сбое CI.
  Агент корутин и `coroutines-debug` подключены только к JVM-тестам, в APK их нет.
  Фикстуры моделей и уведомлений дожидаются отмены своих слушателей и DataStore до закрытия Room и сброса среды.
  DataStore 1.3.0 исправляет гонку нового читателя с записью (upstream I6a427, b/431787506): в 1.1.7 старое содержимое
  могло получить новую версию, после чего читатель пропускал реально записанное обновление. Управляемый тест Storage
  воспроизводит прежний сбой; увеличение таймаутов и смена главного диспетчера не исправляют потерянное событие.
- Android нужного SDK для Robolectric (`android-all-instrumented`) Robolectric качает сам, не через Gradle, — с Maven
  Central в `~/.m2` при первом тесте. В CI этот каталог кешируется по версии Robolectric и набору SDK тестов
  (`robolectric.properties` и `@Config(sdk = …)`): без кеша каждый прогон качал заново, Maven Central ответил 429 и тесты
  упали не из-за кода (master #458, решение 532). Новый SDK в тестах меняет ключ — первый прошедший прогон его сохранит.
- Android Lint — его ошибки роняют CI.
- Эмулятор (задание CI «Android (эмулятор)», Android 14 x86_64 с KVM; локально — запущенный эмулятор и
  `scripts/get-xray.sh && scripts/android-test-server.sh`, затем `android/gradlew -p android :app:connectedDebugAndroidTest`):
  настоящий туннель — VpnService, ядро libXray и сервер Xray на машине CI (эмулятор видит ее как 10.0.2.2). Проверочный
  адрес 1.1.1.1:18081 напрямую не отвечает, а сервер отправляет соединения на порт 18081 на свой HTTP — ответ
  «pg-tunnel-ok» значит, что трафик шел через туннель; после отключения адрес снова недоступен. Адрес публичный:
  диапазоны документации клиент сам закрывает как особые сети (решение 446). Согласие на VPN тест
  выдает сам (`appops set … ACTIVATE_VPN allow`): системное окно в проверке не нажать. Без сервера тест пропускается.
  Там же — жизнь туннеля: Doze без зарядки, выключенный экран и «неактивное» приложение (`dumpsys deviceidle
  force-idle`, `am set-inactive`) — трафик идет через туннель, переподключения нет; смена сети (`svc wifi disable` —
  сеть по умолчанию становится мобильной, потом Wi-Fi обратно) — служба идет следом, трафик снова через туннель за
  90 с, состояние — «Защищено».
  Перед сном проверяется HTTP через TUN, перед пробой во сне — фактический `PowerManager.isDeviceIdleMode`.
  После отключения тест ждет удаления своей сети VPN в том же пределе 15 с.
  В CI `requireTunnelServer=true` запрещает пропуск при недоступном сервере. При ошибке до очистки сохраняются состояние
  туннеля и сети, выбранные поля idle/netpolicy/connectivity и пробы только к тестовому хосту: сокет приложения по
  умолчанию, сокеты конкретных сетей без VPN и сокет shell. Проба по умолчанию при живом VPN тоже может идти через TUN;
  явная сеть и результат связывания подписаны отдельно, секреты скрывает `SecretMasker`.

Не проверено тестами CI: Keystore на настоящем устройстве, «Постоянная VPN» и блок без VPN (включаются только в
настройках Android), энергосбережение производителей телефонов — проверка на телефоне.

### Регрессии аудита 2026-10-29

Проверяются выбор именно своей VPN-сети (включая старые Android и передачу карты), закрепление всех HTTP-перенаправлений
на выбранном пути и закрытие запроса при отмене. Правка текста и смена источника импорта сбрасывают прежний предпросмотр;
ответ закрытого или измененного импорта отбрасывается и после разбора. Публичное уведомление туннеля не содержит имени
сервера. Android policy разрешает намеренно поддерживаемые HTTP-подписки.
