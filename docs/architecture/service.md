# Служба и IPC

Код — `desktop/src/Client.Service` (служба), `Client.Infrastructure/Service` (клиент в интерфейсе),
контракт — `shared/specifications/ipc/gateway_service.proto`, перевод — `ContractMapping`, тесты —
`desktop/tests/Network/ServiceIpcTests`.

## Два режима запуска

| | Установленная служба | Служба пользователя (`--user`) |
| --- | --- | --- |
| Права | администратор / root | пользователь |
| Режимы | VPN и прокси | только прокси; VPN — отказ `PGC-SVC-004` |
| Адрес IPC | Windows — pipe `PrivateGateway.Ipc.v1`; Linux — `/run/private-gateway/ipc.sock`; macOS — `/var/run/private-gateway/ipc.sock` | Windows — pipe `PrivateGateway.Ipc.v1.<пользователь>`; Linux — `$XDG_RUNTIME_DIR/private-gateway/ipc.sock`; macOS — во временной папке пользователя |
| Кто запускает | установщик (этап 3) | интерфейс, когда установленной службы нет и выбран режим прокси |

Один и тот же исполняемый файл и один контракт: «Работать в режиме прокси» без установленной
службы (доска 16) — это служба пользователя. Для разработки — `--ipc <адрес>` и `--xray <путь>`.

## Канал и доступ

- gRPC по HTTP/2 без TLS через Kestrel: Unix-сокет или named pipe, в сеть служба не слушает.
- Unix-сокет: служба пользователя — папка 0700 и сокет 0600; системная служба — сокет 0666, но
  каждое подключение проверяется: uid собеседника берется у ядра ОС (`SO_PEERCRED` на Linux,
  `LOCAL_PEERCRED` на macOS) и должен быть root, uid самой службы или владельца (`--owner <uid>`,
  его передает установщик). Чужой uid — соединение закрывается, запись в журнале.
- Named pipe: список доступа — пользователь службы, администраторы и SYSTEM; вход по сети (SMB)
  запрещен явно.
- Клиент (`IpcChannel`) на каждом соединении проверяет, кто на том конце: у pipe — владельца, у
  Unix-сокета — uid процесса от ядра ОС (тот же `PeerCredentials`). Установленной службе доверяют,
  только если это SYSTEM, администраторы или root; службе пользователя — еще и сам пользователь.
  Процесс администратора с повышенными правами создает pipe от имени группы администраторов, а не
  своего — поэтому администраторам доверяют и как службе пользователя (у них и так вся машина).
  Чужой пользователь, занявший адрес раньше службы, ключей серверов не получит.
- Соединение ждет не дольше 2 с (pipe, которого нет, иначе ждали бы вечно); служба не ответила —
  в окне «Ошибка» с `PGC-SVC-001`.

## Подключение (сейчас — режим прокси)

1. `Connect`: сервер и настройки переводятся из контракта; незаданное — `PGC-SVC-003`, режим VPN —
   `PGC-SVC-004`/`PGC-SVC-006`, сервер не для Xray — `PGC-SVC-005`. Отказ — это состояние службы:
   прежнее ядро останавливается (просили другой сервер — старый не работает молча), `Connecting` →
   `Error` с кодом, его видят все окна. Ответ `ConnectReply` несет тот же код.
2. Конфиг ядра служба собирает сама (`XrayConfigBuilder`), ядро запускается отдельным процессом,
   конфиг — через stdin. Ключи подключения журнал вырезает дословно, остальное — `SecretMasker`.
3. Состояние: `Connecting` → `Connected`, когда ядро открыло вход прокси на 127.0.0.1; не открыло
   за время подключения или вышло само — `Error` с `PGC-SVC-002`, ядро останавливается.
4. Смена сервера — новый `Connect`: старое ядро останавливается, его выход ошибкой не считается
   (номер подключения). `Disconnect` — ядро останавливается, `Off`.
5. `WatchStatus` присылает текущее состояние и каждое новое; `WatchLog` — последние записи журнала
   и новые; `MeasureLatency` — задержка через ядро (`LatencyProbe`), цель без сервера — «не
   поддерживается». Служба останавливается — потоки закрываются сразу, остановка не ждет окон.

## Интерфейс и служба

- При запуске окно ищет службу (`ServiceLocator`): сначала установленную (у нее есть режим VPN),
  потом службу пользователя; каждый адрес ждет 300 мс. Нашлась — `ServiceGatewayClient`, нет —
  имитация `SimulatedGatewayClient` и значок «демо». Служба, запущенная после окна, видна после
  перезапуска окна — до экрана «Служба не запущена» (доска 16) с повтором.
- `ServiceGatewayClient`: состояние и журнал — потоками `WatchStatus` и `WatchLog`, обрыв —
  переподключение через 2 с. Поток состояния оборвался, а защита была включена или включалась —
  в окне «Ошибка» с `PGC-SVC-001`: защита без службы не подтверждена. Вернулась служба — окно
  берет ее состояние.
- `Connect` собирает запрос из описания сервера с ключами (из хранилища ОС) и текущих настроек;
  описания нет (сервер удален) — запрос без сервера, служба откажет и остановит прежнее
  подключение. Отказ приходит состоянием службы, своего окно не выдумывает.
- Пинг своих серверов меряет служба (`MeasureLatency`), каталог записывает его в базу; без службы
  «Обновить» говорит, что пинг меряет служба, а она не запущена, прежние значения не стираются.
- С настоящей службой демо-серверов нет: подключиться к ним она не может, список пуст до первого
  импорта.
