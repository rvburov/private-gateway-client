# Коды ошибок

Каталог — `Client.Core/ErrorCodes`. Служба присылает код (`ErrorInfo.code`, `Status.error`),
интерфейс показывает свой текст на языке пользователя; в журнале — код и подробности без секретов.
Код выглядит как `PGC-<область>-<номер>`: SVC — служба и ядро, NET — сеть.

| Код | Когда | Что видит пользователь |
| --- | --- | --- |
| `PGC-SVC-001` | служба не запущена или не установлена; служба не ответила на подключение или пропала, пока защита была включена; служба пользователя не запустилась (код ставит само окно) | экран «Служба не запущена» (доска 16): работать в режиме прокси (служба пользователя), позже — установить службу; на главной — «защиты нет, трафик идет напрямую» |
| `PGC-SVC-002` | ядро не запустилось, не открыло вход за время подключения, порт прокси занят другой программой (проверка до запуска) или ядро не поднялось при переподключении | «Ошибка службы», код в строке под заголовком |
| `PGC-SVC-003` | запрос не разобран: незаданные значения, данные не того протокола, порт вне 1–65535, сервер удален из списка | отказ подключения — «Ошибка» с кодом |
| `PGC-SVC-004` | режиму VPN нужны права администратора: служба запущена без них (служба пользователя) | экран «Нужны права администратора» (доска 16): работать в режиме прокси или отмена |
| `PGC-SVC-005` | ядро не возьмется за сервер: нет ключа, транспорт не тот, Hysteria2 и TUIC без сборки sing-box (на Android — всегда), VLESS или Trojan без TLS к открытому адресу — трафик шел бы открытым (решение 474) | отказ подключения с объяснением |
| `PGC-SVC-006` | режим VPN недоступен: нет блока при обрыве (Linux без nftables — iptables без nft не поддерживается, решение 183), сборки sing-box или устройства TUN (Linux: контейнер без проброса `/dev/net/tun`, ядро без модуля `tun`) | отказ подключения с причиной: что поставить, сказано в тексте |
| `PGC-SVC-007` | блок при обрыве не включился или не обновился, когда появился адаптер туннеля: правила брандмауэра не поставить | «Ошибка», ядра не запускаются или останавливаются; что с трафиком — по тому, стоит ли блок |
| `PGC-SVC-008` | блок при обрыве (или правила «только туннель») сняла или разобрала другая программа: `nft flush ruleset`, перезапуск службы брандмауэра — служба заметила это сама (сторож блока) | запись в журнале: блок поставлен снова; не встал — тут же `PGC-SVC-007` в журнале |
| `PGC-SVC-009` | служба уже работает с этой папкой состояния (замок `service.lock`): вторая копия не запускается — иначе она сняла бы ядра первой, правила ее туннеля и ее адрес IPC | вторая копия пишет код в stderr и выходит с кодом 2; окно говорит с первой |
| `PGC-NET-001` | сервер не отвечает: проба связи не прошла, переподключение кончилось по политике («До 5 минут», «Не повторять») | в режиме прокси и в VPN без блока — «Ошибка», не «Блокировка»: перекрывать нечем; в VPN с блоком — «Блокировка» без кода: «Интернет заблокирован · Сервер не отвечает» |
| `PGC-NET-002` | адрес сервера не найден: имя не разрешилось ни через систему, ни (под блоком без туннеля) через DoH самой службы | отказ подключения. Под блоком при обрыве — «Блокировка»: «PGC-NET-002 · под блоком адрес не найти: отключите защиту»; отключение снимает блок, следующее подключение найдет адрес. Без блока — «Ошибка», защиты нет |
| `PGC-NET-010` | режим VPN: туннель другой программы держит маршрут ко всему интернету (0.0.0.0/0, ::/0 или их половины) — при подключении или включился на ходу (подключение остановлено, блок при обрыве остается) | экран «Работает другой VPN» (доска 16): проверить снова или продолжить вопреки ему — до отключения; имя адаптера — в журнале |

Отказ подключения режима VPN с блоком, пока блок при обрыве стоит, сеть не открывает: «Блокировка» с кодом
(«{код} · трафик заблокирован»), а не «Ошибка».

Новый код — строка здесь, константа в `ErrorCodes` и текст `error.<код>` в `shared/specifications/localization` на двух
языках (уведомление «Защита не работает» показывает код словами: «Адрес сервера не найден · PGC-NET-002»); номер не
переиспользуется. Все три держит тест `ErrorCodesTests`.
