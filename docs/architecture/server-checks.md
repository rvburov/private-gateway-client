# Проверки серверов и загрузка подписок — 0.1.4

Главный экран показывает флаг или Землю только вместе с видимым IP. Если адреса нет,
показан прочерк без значка; при скрытии адреса значок также скрыт.

Список различает четыре результата: прочерк (не проверяли), многоточие (проверяем),
время в мс (ответ получен), «нет» (попытка не удалась). Карточка сохраняет категорию отказа
и время последней попытки. Миграция 0007 добавляет эти поля, старый null не считается отказом.
Это время HTTP(S)-запроса через профиль в текущей сети, а не ICMP и не скорость скачивания.
Если уже работает VPN, пробы других профилей также зависят от его маршрутов; они не отключают
его и не обходят Kill Switch. Активный профиль использует действующее ядро. Остальные пробы
получают текущие настройки соединения. При блокировке без туннеля выводится причина блокировки.
После неудачи контрольного запроса разрешена одна повторная проба через тот же SOCKS-вход;
для штатной цели запасная — HTTPS на 1.1.1.1, чтобы отделить отказ DNS контрольного домена.
Каждая попытка ограничена 5 секундами, число параллельных проб — 8. Смена сессии отменяет
применение результата. Успех сайта проверки не гарантирует доступность каждого сайта.

«Выходной IP» в карточке — последний измеренный адрес для конкретного профиля, без обрезки.
До измерения — «Не измерен». Он не доказывает внутреннюю цепочку узлов на сервере и не переносится
на соседний профиль той же подписки. Совпадение со входным IP не доказывает отсутствие прокси.

Первый импорт и обновление подписки используют общий SessionSubscriptionDownloader.
При активном VPN/прокси — парольный вход текущего ядра через IPC; без подключения — системный
транспорт. В состояниях подключения, переподключения, блока и ошибки прямой повтор запрещен.
При смене сессии результат отклоняется. Не более трех попыток, до 6 секунд на попытку,
общий срок 20 секунд. Повторяются только временные сетевые ошибки и HTTP 408/429/500/502/503/504.
Retry-After соблюдается: если ждать дольше общего срока, загрузка завершается ошибкой без раннего
повтора. Ошибки сертификата, отказ доступа, слишком большой ответ и невалидный формат не маскируются.
Журнал содержит категорию, HTTP-код, номер попытки, путь (через ядро/системная сеть) и длительность;
адрес подписки, ключи и тело ответа не записываются. Причина пяти попыток из отчета пользователя
не установлена: в старом отчете нет событий импорта. Новый журнал предназначен для такого разбора.

## Проверка пользователем

1. Обновить приложение и службу до 0.1.4, сверить обе версии в «О программе».
2. При отключенных сторонних VPN открыть список и обновить задержки. Непроверенный профиль
   сначала имеет прочерк, во время проверки — многоточие, затем число или объяснимый отказ.
3. Подключить рабочий профиль и повторить проверку. Проверить карточку: полный выходной IP,
   время/причину замера; выбранный сервер сам не меняется.
4. Проверить импорт своей подписки с отключенной защитой и с активным VPN. При обрыве во время
   загрузки прямого обхода быть не должно. Не отправлять действующую ссылку в отчет или чат.
5. Во время подключения IP еще отсутствует — значка нет. После измерения есть адрес и флаг/Земля.
   Скрытие адреса скрывает и значок.
6. При повторной ошибке экспортировать отчет сразу после нее, приложить время попытки,
   версии приложения/службы и снимок сообщения без ссылки подписки.

Локальные тесты используют поддельные ответы и настоящие ядра только на loopback. Они не заменяют
проверку маршрутов, DNS и брандмауэра на M4. Установленная служба и системная сеть при разработке
не менялись; проверки TUN/PF с правами root остаются в одноразовом CI и у пользователя.
