# Архитектура десктопа

Десктоп — два процесса и готовые ядра. Интерфейс работает с правами пользователя и не трогает
сеть; все, что меняет сеть машины, делает служба с правами администратора.

```
┌──────────────────────────────┐   gRPC по named pipe /    ┌───────────────────────────────┐
│ PrivateGateway (интерфейс)   │   Unix-сокету, контракт   │ PrivateGateway.Service        │
│ права пользователя           │ ────────────────────────▶ │ права администратора / root   │
│                              │   shared/specifications/  │                               │
│ Client.UI                    │   ipc/*.proto             │ Client.Service                │
│  └ Client.Application        │                           │  ├ Client.Network (конфиг)    │
│     ├ Client.Network (разбор)│ ◀──────────────────────── │  └ Client.Platform.<ОС>       │
│     └ Client.Contracts       │   состояние, журнал, пинг │      TUN, блок при обрыве, DNS│
│ Client.Infrastructure        │                           │                               │
│  SQLite, секреты ОС, журнал, │                           │  запускает ядра отдельными    │
│  загрузка списков серверов   │                           │  процессами: xray, sing-box   │
└──────────────────────────────┘                           └───────────────────────────────┘
```

## Слои

| Проект | Что внутри | Может ссылаться на | Сеть |
| --- | --- | --- | --- |
| `Client.Core` | модели и правила без ввода-вывода: состояния защиты и переходы, протоколы, маскирование секретов, интерфейсы платформы | — | нет |
| `Client.Contracts` | контракт IPC (код из `.proto`) и перевод перечислений ядра в контракт | Core | — |
| `Client.Network` | разбор ссылок и подписок, сборка конфигов ядер, правила «зашифрован ли трафик» — чистые функции | Core | нет |
| `Client.Application` | сценарии: подключение, смена сервера, импорт, обновление серверов, проверка | Core, Contracts, Network | нет |
| `Client.Infrastructure` | SQLite, секреты в хранилище ОС, Serilog, клиент службы по IPC, загрузка списков серверов | Core, Contracts, Application | только загрузка списков |
| `Client.UI` | Avalonia: окна, модели представлений, тема из токенов | Core, Contracts, Application, Infrastructure | нет |
| `Client.Service` | служба: сервер IPC, запуск ядер, состояние защиты, пинг, проверки | Core, Contracts, Network, Platform.* | да |
| `Client.Platform.Windows` | Wintun, WFP, служба Windows, определение сети (WLAN API, NLM) | Core | да |
| `Client.Platform.Linux` | nftables, systemd, systemd-resolved, polkit, NetworkManager | Core | да |
| `Client.Platform.MacOS` | Network Extension или launchd + utun + pf — решение на спайке | Core | да |

Правила держат тесты `desktop/tests/Architecture` (объявленные ссылки в `.csproj` и
используемые сборки) и анализатор запрещенных вызовов (`desktop/BannedSymbols.NoNetwork.txt`).

## Ход подключения

1. Пользователь добавляет профиль: ссылка, QR, файл или адрес подписки. `Client.Network`
   разбирает текст в модели ядра, `Client.Infrastructure` сохраняет профиль в SQLite, ключи — в
   хранилище ОС.
2. Кнопка-щит: `Client.Application` собирает `ConnectRequest` — описание сервера и настройки
   защиты — и отправляет службе.
3. Служба проверяет запрос (UNSPECIFIED и неизвестные значения — отказ), собирает конфиг ядра
   сама, включает блок при обрыве **до** запуска ядра, поднимает TUN, запускает ядро.
4. Служба меряет внешний IP, проверяет DNS и IPv6 и шлет `Status` в поток `WatchStatus`. Главный
   экран, трей и уведомления показывают одно и то же состояние.

## Состояния защиты

`Off → Connecting → Connected`; из `Connected` — `Reconnecting` (обрыв), `Connecting` (смена
сервера), `Error`, `Off`. `Reconnecting → Connected | Blocked | Error | Off`. `Blocked` и `Error`
восстанавливаются только через `Connecting`. Выключить можно из любого состояния. Трафик идет
мимо туннеля только в `Off`. Таблица переходов — `ConnectionStateMachine`, тесты — `Unit`.

## Связь интерфейса и службы

- gRPC по локальному каналу: named pipe на Windows, Unix-сокет на Linux и macOS. В сеть служба
  не слушает.
- Доступ к каналу — только у пользователя, установившего службу, и у администраторов (ACL
  канала).
- Служба не принимает готовый конфиг ядра, пути к файлам и команды — только описание сервера и
  настройки. Конфиг с путями для логов, записанный от имени администратора, был бы способом
  повысить права.
- Контракт версионируется пакетом (`privategateway.ipc.v1`); интерфейс первым вызывает
  `GetServiceInfo` и сверяет версию.

## Хранение

| Что | Где |
| --- | --- |
| Профили, подписки, настройки | SQLite в папке данных пользователя |
| Ключи, пароли, UUID, адреса подписок | хранилище ОС (`ISecretStore`): Windows — DPAPI текущего пользователя, зашифрованное значение в таблице `secrets`; macOS — Связка ключей (служба «PrivateGateway»); Linux — Secret Service через libsecret. Нет хранилища — секреты не сохраняются вовсе |
| Журнал интерфейса | файл в папке данных пользователя, через `SecretMasker` |
| Журнал службы | системный каталог службы, через `SecretMasker`; интерфейс читает через `WatchLog` |
| Ядра | `runtimes/` при разработке (скачиваются скриптом), каталог установки — в выпуске |
