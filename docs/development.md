# Разработка и сборка

Один путь для каждой ОС: как запустить программу из исходников и как собрать установщик. Все команды — из корня
репозитория: на Windows — в **Git Bash** (в PowerShell и cmd скрипты `scripts/…` не запустятся), на macOS и Linux — в
Терминале. Обычному пользователю это не нужно: ему — установщик ([docs/user/guide.md](user/guide.md), «Установка»).

## 1. Один раз: что поставить

.NET 10 SDK — **для всей машины**: служба работает от имени системы и .NET, поставленный только для вашей учетной
записи (скрипт dotnet-install, расширение VS Code), не видит.

| ОС | Команда |
| --- | --- |
| Windows | в PowerShell: `winget install Git.Git Microsoft.DotNet.SDK.10`; нет `winget` — установщики с https://git-scm.com и https://dotnet.microsoft.com/download (SDK 10). Дальше только Git Bash |
| Debian, Ubuntu | `sudo apt-get install -y git curl unzip dotnet-sdk-10.0` |
| Fedora | `sudo dnf install -y git curl unzip dotnet-sdk-10.0` |
| macOS | `xcode-select --install`, затем `brew install --cask dotnet-sdk` (нужен Homebrew) |

Для установщиков нужен еще Go: `scripts/publish.sh` собирает им геобазу сайтов (`geosite.dat`) из исходников
v2fly/domain-list-community. Без него сборка выпуска остановится на «Нет go — геобазу сайтов не собрать».

| ОС | Команда |
| --- | --- |
| Windows | в PowerShell: `winget install GoLang.Go`, со Scoop — `scoop install go`; нет ни того ни другого — установщик `…windows-amd64.msi` с https://go.dev/dl/. Затем открыть Git Bash заново |
| Debian, Ubuntu | `sudo apt-get install -y golang-go` |
| Fedora | `sudo dnf install -y golang` |
| macOS | `brew install go` |

Проверка — `go version`. И еще по одному инструменту под установщик своей ОС (раздел 4).

## 2. Получить исходники

Первый раз:

```bash
git clone https://github.com/rvburov/private-gateway-client.git
cd private-gateway-client
```

Папка уже есть — обновить:

```bash
cd путь/к/private-gateway-client
git status                       # «On branch master», «nothing to commit, working tree clean»
git checkout master && git pull
```

`git status` перечисляет измененные файлы или `git pull` отказывает — остановитесь и ничего не удаляйте: это ваши
правки, их сначала нужно сохранить.

## 3. Запуск при разработке

```bash
scripts/get-xray.sh && scripts/get-singbox.sh   # ядра со сверенной суммой; после git pull повторить не вредно
dotnet build PrivateGateway.slnx                 # окно и служба, в первый раз — пара минут
dotnet run --project desktop/src/Client.UI       # окно
```

- `dotnet run --project desktop/src/Client.UI -- --demo` — окно на имитации службы, с демо-серверами: ничего не
  ставит и сеть машины не трогает. Для работы над интерфейсом.
- Служба: окно само предложит «Установка службы» → «Установить» (права администратора спросит система). После
  `git pull` и сборки «Настройки» → «О программе» покажет, что служба из других исходников, — «Обновить службу».
  Служба не отвечает — там же «Переустановить службу».
- Перед `dotnet build` закройте запущенную программу (значок в трее → «Выход»): иначе сборка упадет на занятых файлах
  («being used by another process»).
- Тесты: `dotnet test --project desktop/tests/Unit` — быстрые, `dotnet test --solution PrivateGateway.slnx` — все.
  Стиль: `dotnet format PrivateGateway.slnx`. Подробнее — AGENTS.md, «Тесты».

### Проверка локальных портов и отчет CI

Номер из `LocalPort.FreeForTcpAndUdp` не резервируется до запуска внешнего ядра. Другой процесс может занять его
после проверки. Поэтому тест не пытается повторно занять уже освобожденный порт: он использует
`ReserveForTcpAndUdp` и проверяет отказ конкурирующих TCP/UDP-сокетов, пока `LocalPortLease` удерживает пару.
TCP проверяется с `Listen`, UDP — с `Bind`, с исключительным использованием адреса. Диапазон обычных кандидатов,
кеш последних номеров и запасной выбор ОС сохраняются. Это исправление контракта проверки, а не обещание
атомарной передачи номера процессу Xray; владелец порта в исторических коллизиях CI не установлен.

В CI обычные тесты, проверки Secret Service и проверки с правами дают самостоятельные результаты. После успешной
сборки независимые шаги своей ОС выполняются и при падении обычного теста; отмена запуска и неуспешная сборка их
останавливают. Первое падение сохраняет красный статус. Итоговый отчет по-прежнему отклоняет запрещенные пропуски:
правила `allowed-skips.json` не расширяются. Отдельный ночной прогон проверяется по своему журналу, а не по отчету
обычного CI.

Ночной прогон намеренно создает сбои и предупреждения. Журнал хранит не более 500 записей, отдавая приоритет
предупреждениям: даже свежая строка запуска ядра может сразу исчезнуть из истории. Поэтому PID ядер стенда
отслеживает тестовый `ServiceCoreTracker` по событию `ServiceJournal.Added`, а не поиском по хвосту журнала.
Он хранит только последний PID прокси и последнюю цельную пару PID туннеля; подписка снимается вместе со стендом.
Короткая регрессия заполняет журнал предупреждениями и проверяет реальные остановки Xray и переподключения.
Это воспроизводит присланную ошибку `Sequence contains no matching element` без ожидания 23 минут, но не заменяет
выпускной прогон по 30 минут на режим на трех ОС. Лимит журнала, пороги ресурсов и проверки утечек не увеличиваются.

Локальная проверка 2026-11-01 после этих исправлений: полный Release-прогон — 1625 тестов, 1508 успешных,
0 ошибок, 117 пропусков с причинами среды (нет прав и нужной ОС для системных проверок). LocalPort — 4/4,
регрессии PID — 3/3; четыре мутанта удержания сокетов и три мутанта получения PID отвергнуты. Короткий
proxy soak — 8 кругов за 1 минуту 6 секунд, 1/1 успешный тест без пропусков. Проверки отчета CI — 6/6.
Это не подтверждает полный ночной прогон, TUN/брандмауэр на трех ОС или работу новой сборки у пользователя.

## 4. Установщик

Установщик собирается на машине той ОС, для которой он: сначала сборка выпуска (`scripts/publish.sh`, ставить .NET
пользователю не нужно — он внутри), затем пакет. Версия — SemVer, по умолчанию из `Directory.Build.props`. Каждый
скрипт в конце печатает, где лежит готовый файл.

### Windows — `.msi`

Один раз: `dotnet tool install --global wix --version 5.0.2` (расширения WiX скрипт ставит сам). Затем в Git Bash:

```bash
scripts/publish.sh 0.1.0
scripts/package-windows.sh 0.1.0
```

Готово: `artifacts\release\PrivateGateway-0.1.0-win-x64.msi` (полный путь — последняя строка вывода). Установка —
двойной щелчок: приветствие → папка установки → «Установить» (Windows спросит права администратора) → «Готово» с
флажком «Запустить Private Gateway». Служба ставится установщиком. Удаление — «Параметры» → «Приложения» →
«Установленные приложения» → Private Gateway → «…» → «Удалить».

Программа из исходников и из MSI — одна и та же служба: перед установкой MSI окно из исходников закройте. Новая
сборка MSI той же версии ставится поверх прежней.

### macOS — `.dmg`

Только на macOS (нужны `codesign` и `hdiutil` — они есть в системе):

```bash
scripts/publish.sh 0.1.0
scripts/package-macos.sh 0.1.0
```

Готово: `artifacts/release/PrivateGateway-0.1.0-osx-arm64.dmg` (на Intel — `osx-x64`). Установка — открыть образ и
перетащить Private Gateway в «Программы»; первый запуск — «Системные настройки» → «Конфиденциальность и
безопасность» → «Все равно открыть» (подписи Developer ID пока нет).

### Linux — `.deb` и `.rpm`

Один раз — nfpm (нужен go): `go install github.com/goreleaser/nfpm/v2/cmd/nfpm@v2.47.0`, и `~/go/bin` в `PATH`.

```bash
scripts/publish.sh 0.1.0
scripts/package-linux.sh 0.1.0
```

Готово: `artifacts/release/private-gateway_0.1.0_amd64.deb` и `private-gateway-0.1.0.x86_64.rpm`. Установка —
`sudo apt install ./artifacts/release/private-gateway_0.1.0_amd64.deb` или
`sudo dnf install ./artifacts/release/private-gateway-0.1.0.x86_64.rpm`; удаление — `sudo apt remove private-gateway`
или `sudo dnf remove private-gateway`.

### Без сборки у себя

CI собирает все три установщика при каждом изменении `master`: GitHub → «Actions» → «Сборка выпуска» → верхний
запуск с зеленой галочкой → «Artifacts» → `release-Windows` (`release-Linux`, `release-macOS`). Выпуск с тегом —
[docs/architecture/release.md](architecture/release.md).

## 5. Частые проблемы

- **Сборка падает на занятых файлах** — запущена программа или ее служба из папки репозитория: закройте окно (трей →
  «Выход») и соберите снова.
- **«wix» не найден** или **«Нет go — геобазу сайтов не собрать»** — wix или Go не поставлены (раздел 1) или терминал
  открыт до их установки: откройте Git Bash заново.
- **Подписка не загружается, а сайт в браузере открывается** — в системе остался прокси другой программы (например,
  выключенного VPN). Программа сама повторит загрузку напрямую; «Проверка» → «Другие VPN и прокси» покажет такой
  прокси.
- **Служба «работает», но окно пишет «Не отвечает»** — «Настройки» → «О программе» → «Переустановить службу»;
  причина — в журнале окна («Экспорт отчета»).

### Полнота интерфейсных тестов на Linux

Для Avalonia.Headless/Skia нужны системные библиотеки fontconfig и их зависимости, а также шрифты. В контейнере
без libfontconfig на SDK 10.0.403 часть AvaloniaFact могла исчезать из итоговой сводки после ошибки очистки:
обнаруживалось 357 тестов UI, а выполнялись только 56 обычных Fact. Поэтому прежние локальные сводки 1505/1508
успешных тестов не подтверждали все интерфейсные сценарии. Сводку нужно сверять с реальным исполнением UI,
а не только с кодом возврата. Новый NativeRendererTests использует обычный Fact и должен явно падать,
если нативный графический backend недоступен (решение 523).

При зависании Actions macOS Intel загружайте артефакт `other-cpu-tests-macos-15-intel`: Trace синхронно фиксирует начатые
тесты, а long-running выводит длительные выполнения. Не все начатые строки означают зависание: сверяйте их
с итоговыми событиями. Предельное время обычного набора не заменяет отдельный выпускной soak.

Итог доработок 2026-11-01 после исправления стенда: полный Release — total 1996 / failed 0 / succeeded 1878 /
skipped 118. По проектам: Unit 995/989/0/6, Architecture 19/19/0/0, Network 623/511/0/112,
UI 359/359/0/0 (в этой строке порядок total/succeeded/failed/skipped). 37 валидных исходных мутантов
отвергнуты assert-проверками: proxy lifecycle 15, VM 7, короткие команды 3, отчет 2, HTTP-проба 4,
совместный вход и IPC 6. Отсутствие fontconfig — отдельная отрицательная проверка обычного NativeRenderer Fact.
Нативные проверки Windows/macOS/Linux с системными правами и полный выпускной soak требуют соответствующих стендов.

После полного прогона короткий proxy soak также прошел: total 1 / failed 0 / succeeded 1 / skipped 0,
8 кругов за 1 минуту 7 секунд. Это smoke-проверка, официальный 30–60-минутный soak остается отдельным условием выпуска.

Сверка с нативным CI: [#446, `8c9b70d`](https://github.com/rvburov/private-gateway-client/actions/runs/41316955616)
прошел Linux, macOS и macOS Intel, но Windows выявил отказ обычного HTTP к FakeDNS через дополнительный прокси
(решение 524). Его отчет: total 1995 / failed 1 / succeeded 1890 / skipped 104; Network 623/520/1/102,
UI 359/359/0/0, Unit 994/992/0/2, Architecture 19/19/0/0 (здесь по проектам total/succeeded/failed/skipped).
Ошибка шага отчета повторяет эту первичную ошибку теста. Локальный зеленый прогон выше не доказывал этот путь:
реальный Windows TUN в облаке пропущен, прежняя localhost-проверка не запрашивала настоящий адрес FakeDNS.
Новая переносимая проверка использует DNS-ответ и таблицу того же ядра; Windows-тест остается с настоящим TUN.

В [проверке #449](https://github.com/rvburov/private-gateway-client/actions/runs/41319377687), коммит `638dc72` другой ветки,
macOS ARM64 снова исполнил старый `LocalPortTests.Port_takes_both_tcp_and_udp`: TCP Bind порта 28335,
итерация 19, `AddressAlreadyInUse`. Это быстрый отказ за 35 мс, а не зависание Intel. Три новых коммита
`638dc72`, `b929700`, `10565b6` меняют только README и не содержат исправления LocalPort (решение 513).
Наш общий результат сохраняет их открытые задачи и проверяет удерживаемую TCP/UDP-пару вместо повторного
занятия освобожденного номера. Владелец порта по неатомарному снимку Closed не установлен. Ошибки отчета
о непройденных root-проверках macOS дополнительно вызваны их пропуском после первой ошибки старого workflow;
такие шаги теперь запускаются независимо, если сборка состоялась и задание не отменено.

Общий исходник поверх `10565b6` (включая три новых пункта README другого агента), решения 524–526:
Release total 2009 / failed 0 / succeeded 1891 / skipped 118. Unit 995/989/0/6, Architecture 19/19/0/0,
Network 636/524/0/112, UI 359/359/0/0 (по проектам total/succeeded/failed/skipped). Девять новых мутантов
отвергнуты: FakeDNS и диагностика HTTP — 5, пауза/жизненный цикл наблюдателя — 4. Старый HTTP `ResponseEnded`
воспроизведен удалением исправления; замена Shadowsocks на loopback отвергается правилами IP Direct/Block.
Полные исходники восстановлены после мутаций и пересобраны, format и actionlint прошли. Это локальный стенд;
нативные Windows/macOS/Linux и длительный выпускной soak подтверждаются отдельно по SHA запуска.
