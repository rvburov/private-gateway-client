# Имена действительно заблокированных соединений Xray

Проверен исходник закрепленного Xray-core 26.10.21, коммит
`1b1647cd9ddf0abc34b981d4611fc03bcac1ca74`, лицензия
[MPL-2.0](https://github.com/XTLS/Xray-core/blob/1b1647cd9ddf0abc34b981d4611fc03bcac1ca74/LICENSE).
Исходный Go-код не переносится и ядро не меняется. Клиент читает существующее сообщение маршрутизатора
собственным ограниченным обработчиком; дополнительный API, слушающий порт или библиотека не добавляются.

## Откуда берется имя

- [app/dispatcher/fakednssniffer.go:29–36](https://github.com/XTLS/Xray-core/blob/1b1647cd9ddf0abc34b981d4611fc03bcac1ca74/app/dispatcher/fakednssniffer.go#L29-L36):
  FakeDNS берет имя из собственной таблицы соответствия адреса и домена. Результат имеет протокол `fakedns`.
- [app/dispatcher/default.go:299–317](https://github.com/XTLS/Xray-core/blob/1b1647cd9ddf0abc34b981d4611fc03bcac1ca74/app/dispatcher/default.go#L299-L317)
  и [354–372](https://github.com/XTLS/Xray-core/blob/1b1647cd9ddf0abc34b981d4611fc03bcac1ca74/app/dispatcher/default.go#L354-L372):
  после успешного распознавания адрес `destination` заменяется доменом; именно измененная переменная передается
  в `routedDispatch`. Это действует и для SNI с `routeOnly`, когда адрес самого соединения остается прежним.
- [app/dispatcher/default.go:455–465](https://github.com/XTLS/Xray-core/blob/1b1647cd9ddf0abc34b981d4611fc03bcac1ca74/app/dispatcher/default.go#L455-L465):
  после выбора правила и проверки наличия его обработчика печатается сообщение Info
  `taking detour [block] for [tcp:blocked.example:443]` либо его вариант с префиксом `Hit route rule: [...] so`.
  Это выбор блокирующего выхода для уже распознанной цели; одно сообщение `sniffed domain` блокировку не доказывает.
- [common/log/log.go:25–27](https://github.com/XTLS/Xray-core/blob/1b1647cd9ddf0abc34b981d4611fc03bcac1ca74/common/log/log.go#L25-L27)
  добавляет уровень `[Info]`, а
  [app/log/log.go:126–137](https://github.com/XTLS/Xray-core/blob/1b1647cd9ddf0abc34b981d4611fc03bcac1ca74/app/log/log.go#L126-L137)
  направляет общее сообщение в приемник `error`, согласно внутреннему уровню журнала. Поэтому приемник
  соединений `access` остается `none`: его исходный адрес назначения не подходит для восстановления имени.

## Границы приема

При наличии правил блока внутри ядра нужен уровень Info. Дополнительные сообщения не повышают выбранный
пользователем уровень общего журнала. На телефонах `error` направляется в закрытый pipe процесса; на десктопе
обработчик получает строку до общего журнала. Только подтвержденная цель выхода `block` попадает в ограниченную
историю текущего дня в памяти. Прочие маршруты, сырые строки посещений, сообщения распознавания и дополнительный
Info отбрасываются. История не входит в диагностический экспорт, резервные копии или телеметрию и очищается при выходе
из аккаунта. Неизвестный адрес FakeDNS не выдается за имя сайта.

Если ядро не восстановило имя, например при недоступном SNI/ECH и отсутствии записи FakeDNS, клиент не угадывает
сайт по общему адресу CDN. Автоматическое разрешение предлагается только настоящему доменному имени.

## Проверка

`desktop/tests/Network/BlockedSiteNamedHistoryTests.cs` запускает закрепленный Xray на петле без TUN, прав
администратора и внешних серверов. Четыре случая запрашивают настоящий адрес FakeDNS и отправляют в HTTP/SOCKS
только этот IP, с распознаванием HTTP/TLS и без него. История должна вернуть домен из таблицы ядра. Отдельный случай
отправляет SOCKS только синтетический IP, а имя — лишь в настоящем TLS ClientHello: блок должен сработать по SNI
до выхода к тестовому приемнику. Даже при сломанном правиле все прямые выходы этого случая направлены только на петлю.
Общие журналы проверяются на отсутствие домена, адреса FakeDNS и сырых сообщений маршрутизации.
